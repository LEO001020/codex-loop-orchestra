**主要漏洞**

A. **Gap：** guard hard deny 后无任何自动 headless 接管路径，有效并发实质下降——与用户约束直接冲突。
B. **双写风险：** 若主/agent 两侧各自补发，无幂等去重，会重复执行。
C. **8765 归因边界：** monitor 在 WSL/Windows 两侧各自汇总 roster，`merge_native_rosters` 依赖 `updated_at` 取新，若 guard deny 的 agent 仍注册在 native roster 一侧且未标记 "routed_to_exec"，会被重复计入两平面。
D. **Desktop 批量绑定：** 当前无 IAB 路由取消分配确认机制，无法证明 native 8 上限实际有效。

**最小修复建议**

1. **Deflection 而非 Deny：** guard 触发时，自动将 spawn 请求转发至 `dispatch_single`（headless exec），在 `native_roster` 记录 `status=deflected_to_exec, exec_agent_id=<uuid>`，保证幂等（同一 tool_use_id 只生成一条）。
2. **8765 plane 归属标签：** 所有 deflected agent 在 exec_roster 中标注 `origin: native_deflected`，monitor 按 `origin` 过滤，native 侧不计入 active。
3. **IAB 取消绑定确认：** guard deny 后等待 500ms 读取 native roster pending 队列，确认该 agent 未出现即视为解绑成功，写入 `lifeiry events.ndjson`。

**最小机械验收方案**

 (i) **目标16未下降：** 在一次 wave 启动中派发17个 packet（第17个必然触发 guard），然后轮询 `data/lifecycle/exec_roster.json` 确认17个均有 `agent_id` + `status != failed`，其中至少9个 `origin=native_deflected`。
 (ii) **headless 补位成功：** 汇总 `exec_roster.json` 中 `origin=native_deflected` 且 `status=running/completed` 的 agent 数量 = wave_size - 8。
 (iii) **无重复执行：** 对所有 `agent_id` 做 `COUNT(DISTINCT)` 对比 native_roster + exec_roster 中该 agent_id 出现次数 = 1。
 (iv) **8765 归因正确：** `GET /api/status` 中 K3 执行面 active 数等于 exec_roster 中 `origin=native_deflected AND status=running` 的数量；native plane active 数 ≤8。
 (v) **Desktop 不再批量绑定：** 检查 `data/governor/gate_decisions.ndjsonl` 中 guard deny 的 packet，在 8765 native plane 中查无该 agent_id 的 `running` 记录。
