**主要漏洞**
- **`deficit`（target−running）未由 API 计算/返回**；UI 只显示 target 与各 pool，不显示缺口值。
- **`initializing` 无 TTL/卡死识别**：pending/spawning 若永久不转 running，会一直保持 initializing（行414/429/468），掩盖卡死的 native 波次。

**最小修复建议**
1. 在 `snapshot()` 返回 `deficit = {pool: max(0, pref[p] − counts.pool[p]), total: max(0, target − counts.running)}`，仅读计算。
2. `initializing` 加展示 TTL 或独立“stuck initializing”计数，超出 TTL 标明为疑似卡死。
3. UI 对 `preferred=0/48` 增加“临时政策”横幅，或恢复显示波次-16 目标并另列“当前 K3 临时上限 48”。
