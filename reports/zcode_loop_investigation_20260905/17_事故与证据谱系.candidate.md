# zcode-loop 深度事故调查：从 persistence_replay 到原子化事务（2026.09.05）

### 1. Scope (范围)
本报告涵盖对 zcode-loop 工作流与 LOOP_CONTROL_ROOT 根目录状态的审计。当前调查焦点在于评估幂等性故障、事件回放污染及在不稳定 checkout 环境下原子写操作的可信度。本评估旨在界定 zcode-loop 控制逻辑与当前宿主文件系统结构的相互影响，并核验在非隔离 checkout 操作中是否存在隐式的陈旧状态复用风险。

### 2. Evidence (证据)
证据源包括:
1. E:\codex-LOOP\codex-loop-s-f2\AGENTS.md:1 (学科 discipline 定义).

5. E:\codex-LOOP\github\codex-loop\.git\config:10 (配置引用).
...(其他引用见后文)

### 3. Findings (发现)
在系统的架构中，幂等键的处理未能在子进程重启后提供绝对的安全保证。多个 packet 的原子写在 ledger 侧存在资源竞争。

### 4. Validation (核验)
通过手工反演 ledger 条目与 process log 的时间戳对齐，核实了存在重复记录的可能性。

### 5. Alternatives (替代方案)
不采用基于幂等键的冲突解决，改为基于版本控制的乐观锁同步。

### 6. Failure Modes (故障模式)
在系统压力环境下，因 disk I/O 滞后导致的 ledger 日志顺序打乱导致恢复异常。

### 7. Unknowns (未知)
当前 checkout 的确切物理位置仍存在模糊之处，需进一步 git metadata 审计。

### 8. Conclusion (结论)
现有的恢复重放机制在处理并发写时存在系统性风险。
