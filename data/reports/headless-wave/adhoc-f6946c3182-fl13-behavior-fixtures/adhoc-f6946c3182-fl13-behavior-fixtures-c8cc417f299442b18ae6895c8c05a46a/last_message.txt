### 重点逻辑核查：preflight 中的关键负向判断路径

以下逻辑已在源码中逐字确认（不是行为夹具，但 token 覆盖精确）：

**Docker false（`P=false`）/ `M=../->` 首中尾三态：**
- docker inspect 格式串中 `P=true` 触发 OPEN，`P=false` 不进入该分支 → **正确，false 不误报**
- mount 路径 `(M=|;)/->` 匹配 host 根挂载（首条）；`(M=|;)/(etc|root|proc|sys|boot|var/lib/docker)->` 匹配子树（中/尾）；`/etc/(shadow|gshadow|sudoers)` 匹配具名危险文件 → **三层递进，f10-1 收窄了误报**

**docker.sock：**
- world-writable（`-perm -002`）→ `note_open "docker.sock is WORLD-writable"` ✅
- group-writable + agent 在 owning group → `note_open "docker.sock group-writable and agent is in owning group"` ✅
- group-writable 但 agent 不在该 group → `note_warn`（--strict 下升级）✅

**privileged / host-namespace：**
- `P=true|PID=host|IPC=host|USERNS=host|SYS_ADMIN|...|\[ALL\]|unconfined` → `note_open "privileged/host-namespace/..."` ✅

**unknown setuid / allowlisted-but-writable：**
- 不在 `$ALLOW` 列表 → `note_open "unexpected setuid/setgid binary (not allowlisted)"` ✅
- **在 allowlist 中但 world-writable** → 仍 `note_open "world-writable setuid binary"` ✅（检查在 allowlist 跳过之后独立执行）
- **在 allowlist 中但 group-writable 且 agent 在 owning group** → 仍 `note_open "setuid binary group-writable by an agent group"` ✅
- f13 cap allowlist 豁免条件：必须同时满足 `cap_agentwritable=no` **且** `root-owned` **且** 在 `$CAP_ALLOW` 中，三者缺一则 OPEN ✅
