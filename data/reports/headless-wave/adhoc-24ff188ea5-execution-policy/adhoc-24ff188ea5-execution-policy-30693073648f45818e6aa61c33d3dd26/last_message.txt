---

## 执行策略安全复核报告

### 评估对象

PowerShell 快捷方式，典型形式：

```
powershell.exe -ExecutionPolicy Bypass -File "E:\codex-LOOP\<script>.ps1"
```

---

### 风险维度逐项分析

**1. `-ExecutionPolicy Bypass` 的持久性影响**

`-ExecutionPolicy Bypass` 是**进程级**参数，作用域仅限于该单次 PowerShell 进程的生命周期，**不会写入注册表**，不改变系统级或用户级执行策略（`HKLM:\SOFTWARE\Microsoft\PowerShell\1\ShellIds\Microsoft.PowerShell\ExecutionPolicy` 和对应 `HKCU` 键均不受影响）。

结论：**不引入持久执行策略变更**，风险可控。但它确实绕过了签名校验，意味着任何内容的脚本都会被执行。

**2. 绝对 `-File` 路径的参数注入风险**

绝对路径本身（如 `E:\codex-LOOP\script.ps1`）**不构成注入向量**，前提是路径被正确引号包裹。若路径含空格而未加引号，存在路径截断风险，但这属于配置错误而非设计缺陷。

关键风险点在于**脚本本身的可写性**（见下一条）。

**3. 脚本可写性风险（核心风险）**

这是本次评估的核心。若 `E:\codex-LOOP\` 目录下的目标 `.ps1` 文件对当前用户或低权限进程可写，则攻击者可通过替换脚本内容实现**任意代码执行**，且因 `-ExecutionPolicy Bypass` 已绕过签名校验，无任何签名防护兜底。

在沙盒只读环境下我无法直接读取 ACL，但根据目录命名（`E:\codex-LOOP`，用户工作区）和当前 shell 为 `powershell`（标准用户上下文），合理推断该目录的 DACL 对当前用户可写。

**4. 当前用户权限**

当前执行上下文为标准用户 PowerShell，无证据显示以提升权限（管理员）运行。快捷方式本身不请求 UAC 提升，因此横向移动面有限。但若快捷方式被放入启动项（`shell:startup`、计划任务、注册表 Run 键），则低权限持久化路径打开。

---

### 综合风险等级

| 风险点 | 描述 | 等级 |
|---|---|---|
| 持久执行策略变更 | 无，进程级 Bypass 不写注册表 | P3（低） |
| 参数注入（路径层面） | 路径已加引号，无截断风险 | P3（低） |
| 脚本文件可写性 | 用户可写目录 + Bypass 签名校验 = 代码替换即执行 | **P1（高）** |
| 快捷方式本身可写 | 若 `.lnk` 可被替换，可指向任意载荷 | P2（中） |
| 整体综合评级 | 由最高单项决定 | **P1** |

---

### 结论与建议

**综合评级：P1（高风险）**

主要风险源不是 `-ExecutionPolicy Bypass` 本身，而是**"绕过签名 + 脚本可写"的组合**。任何能写入 `E:\codex-LOOP\` 的进程或用户都可以在下次快捷方式触发时执行任意代码，且无签名拦截。

修复建议（按优先级）：

1. **收紧脚本文件 ACL**——移除非必要写权限，确保只有受信任的进程可修改 `.ps1` 文件。
2. **对脚本进行代码签名**，改用 `-ExecutionPolicy AllSigned` 或 `RemoteSigned` 替代 `Bypass`，恢复签名校验作为兜底防线。
3. **收紧快捷方式 `.lnk` 的 ACL**，防止目标路径被重定向到恶意脚本。
4. 若需定期调度，使用计划任务并限定运行账户权限，避免将高权限账户绑定到可写脚本。
