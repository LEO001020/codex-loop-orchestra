## Dynamic Test Expectation Audit — Findings

**Scope:** All `tests/**/*.py` excluding `*ipybox*` files. K3 tests excluded by function (K3-behavior tests are intentionally testing K3 routing; those are not "hard-coding" problems). ### CLASS D — `test_model_profile.py` profile registry (bounded but noteworthy)

`tests/unit/test_model_profile.py` lines 40–51 enumerate all five profiles with their exact `(execution_model, reasoning, review_model, review_reasoning)` tuples. This is intentional — it is a declarative contract test for the profile switcher. However:

- The `"k3-only"` profile hard-codes `"weiwu-k3/kimi-k3"` for both slots, which is intentional for that profile.
- The `"v4f-sonnet-review"` entry hard-codes `"weiwu/aws.claude-sonnet-4.6"`, `"ultra"` for the review role, which is the current active profile.

**This test is the right place to put literal profile expectations.** The issue is **no `v4f-sonnet-review` health fixture** exists (only `k3.json`). In `orchestration_v2/conftest.py` the provider health fixture is still `k3.json` with `"weiwu-k3/kimi-k3"`. When routing mode is `cold_start` this doesn't break routing, but the conftest fixture will produce incorrect `provider_health` state for the active profile's review model.
