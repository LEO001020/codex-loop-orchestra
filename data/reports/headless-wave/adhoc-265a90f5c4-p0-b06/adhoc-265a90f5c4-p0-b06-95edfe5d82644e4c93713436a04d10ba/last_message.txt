## 审计结论：8765不可用时controller回退roster行为 + fail-visible字段判断

### 降级路径分析

**代码定位：** `harness/refill_controller_v2.py`，`_read_observer_snapshot()` 方法（第360-381行）和 `_read_roster_state()` 调用点（第335-358行）。

#### 8765不可用时的实际回退行为

`_read_observer_snapshot()` 在以下任意情况返回 `None`：
1. 网络连接失败 / `OSError` / `TimeoutError`（0.35s超时）
2. 响应无效或 `freshness` 不在 `{"LIVE", "QUIET", "ESTIMATED"}` 中
3. 快照时间戳超过5秒（过旧）
4. 响应中的 `root`/`windows_root` 与本地root路径不匹配

返回 `None` 时，`_read_roster_state()` 中的 overlay 块（`if observer is not None:`）**完全跳过**，仅凭本地双roster：
- `native_roster.json`（Desktop原生 agent 状态）
- `exec_roster.json`（headless lifecycle supervisor 状态，并做进程活跃度校验）

这是**正确的降级设计**：overlay 的语义是 `max(local, observer)`，而非 `observer` 强制替换。8765缺失时回退到纯本地计数，不会丢失数据，不会停服务。

### 是否需要新增 fail-visible 字段

**判断：需要，但当前代码缺失。**

#### 缺失点

当前 `recompute()` 输出的 `state` 字典（第512-537行）**不包含任何 observer 可观测性字段**：

| 字段 | 当前状态 |
|------|---------|
| `observer_available` | **缺失** |
| `observer_freshness` | **缺失** |
| `observer_source` (local vs 8765) | **缺失** |
| `active` 字段的数据来源标注 | **缺失** |

#### 风险

持久化到 `data/refill/refill_state.json` 的 `active.{v4,k3}` 数值，在8765不可用时可能**低于真实值**（因为无法跨平面聚合），但读取方（主代理、外部观察者）**无法区分**这两种情况——它们看到的 state 字段结构完全相同。

LOOP 规则明确：

> "Only observed running agents (native roster) reduce the deficit, so an undercounted `active` is fail-visible: debt stays non-zero."

但这里的问题是：当 observer 不可用时，`active` 可能**系统性偏低**，导致 `deficit` **虚高**，进而触发不必要的 refill。更关键的是，主代理或监控面板**无从判断**当前数字是否来自跨平面聚合，无法对告警进行分级。

#### 建议新增字段

在 `recompute()` 的 `state` 字典中应增加：

```python
"observer_status": {
    "available": observer is not None,           # 是否成功读取8765
    "freshness": observer.get("freshness") if observer else None,
    "timestamp": observer.get("timestamp") if observer else None,
},
```

同时，在 `_read_observer_snapshot()` 内部，各类失败原因（网络超时、freshness无效、root不匹配、时间戳过旧）应单独可区分记录，而非统一返回 `None` 且无任何侧效果。

---

### 总结

**回退行为本身是安全的**：8765不可用 → `_read_observer_snapshot()` 返回 `None` → overlay跳过 → 仅使用本地 native + exec 双roster → 不停服务，不丢数据，`deficit` 保持 fail-visible（偏保守而非偏宽松，不会过度放行 spawn）。

**需要 fail-visible 字段**：当前 `refill_state.json` 没有 `observer_status` 字段，外部无法判断 `active` 计数是否包含8765跨平面数据，无法对 "虚高 deficit → 多余 refill 事件" 告警进行溯源，属于可观测性缺口，**建议补充**。测试文件（`test_refill_controller_v2.py`）中也无任何 observer 降级场景的覆盖，建议同步补测。
