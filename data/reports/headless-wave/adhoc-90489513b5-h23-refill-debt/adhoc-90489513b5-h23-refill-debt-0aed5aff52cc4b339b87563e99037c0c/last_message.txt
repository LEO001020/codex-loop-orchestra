## Sustained Refill Debt Audit — Findings

### Summary

Desktop concurrency decays after terminal tasks due to **three interacting structural gaps** across lifecycle close, controller backlog, and birth debt semantics. None individually is catastrophic, but their combination reliably produces a stale-high `running` count that suppresses refill debt, followed by a delayed collapse to a low-and-frozen count once the TTL fires.

---

### Finding 1 — Native roster TTL creates a delayed, abrupt slot release

**Location:** `refill_controller_v2.py` → `_read_roster_state()`, lines ~300–306

```python
if observed_at <= 0 or now - observed_at > NATIVE_RUNNING_TTL_SECONDS:
    continue
```

`NATIVE_RUNNING_TTL_SECONDS = 1800.0` (30 minutes). Desktop-native agents appear in `native_roster.json` with `status = "running"` but their `updated_at`/`started_at` timestamp is only set when the native SubagentStart hook fires. Once the Desktop agent completes, **no hook rewrites the row to a terminal state**—that requires an explicit `close_agent` call, which only the Codex host runtime can issue.

The result: after a terminal task, the native roster continues counting those agents as `running` until the 30-minute TTL expires. The refill controller's `_read_roster_state()` returns `running = N` (as if the agents are still alive) so `recompute()` sees no deficit and emits no `refill_required` event. **Concurrency appears healthy but is actually decaying.** At T+1800s, all those rows expire simultaneously and `running` drops to 0—the full 20-agent deficit materializes at once, causing a burst of birth attempts.

The v1 controller had the same TTL vulnerability. The 8765 observer path in v2 (`_read_observer_snapshot()`) is supposed to be the cross-plane authority and can override local stale rows, but it has its own 5-second freshness requirement (`time.time() - float(...) > 5.0 → return None`), and if the observer is unavailable or returns `foreign_root`, the local stale native roster is used verbatim.

---

### Finding 2 — Desktop edge `close_agent` is out-of-band and has no automatic trigger

**Location:** `desktop_edge_reconcile.py`, `lifecycle_supervisor.py` docstring (line 13–15)

The supervisor's docstring explicitly states:

> "Desktop-native subagents are deliberately out of scope: hooks can reconcile their shadow roster and **request a host `close_agent` call**, but only the Codex host runtime can release those native slots."

There is no automatic scheduling path that calls `close_agent` when a Desktop-native agent terminates normally. The `schedule_epilogue()` path at the end of `lifecycle_supervisor.py`'s `run()` function is triggered only for headless `exec` workers (the `packet_file.is_file()` branch routes to `refill_consumer_v2`; without a canonical packet file it falls through to the adhoc path). Desktop-native agents that complete without a lifecycle-supervised process have **no epilogue scheduling**.

`desktop_edge_reconcile.py`'s `apply_plan()` method is an **offline maintenance action** that:
- requires `--apply` to be explicitly passed,
- refuses to run while any Codex Desktop process is present (`desktop_running()` check),
- requires a manual `--backup-dir` argument.

This means stale `open` edges in the Desktop state DB (`thread_spawn_edges`) are never automatically cleaned. Each `open` edge holds an active host slot. The refill controller's `_read_roster_state()` reads `native_roster.json` for running counts, but the native roster is populated by hooks (SubagentStart), not by the Desktop state DB directly. After terminal the native row stays `running` (Finding 1) and no automatic `close_agent` fires to transition it to `terminal`.

### Finding 3 — `initializing` births reserve capacity but never clear deficit; stale initializing rows suppress refill without confirmed birth

**Location:** `refill_controller_v2.py` → `recompute()`, lines ~415–425

```python
raw_spawn = {p: max(0, raw_debt[p] - initializing[p]) for p in POOLS}
capacity = max(0, target_total - running_total - initializing_total)
deficit_total = min(sum(raw_spawn.values()), capacity) if required_any else 0
```

The exec roster's `starting` state maps to `initializing` in `_read_roster_state()`, and the supervisor process-generation liveness check (`_process_generation_alive`) gates whether a `starting` row is counted:

```python
if not supervisor_alive or (key == "running" and not worker_alive):
    continue
```

For `initializing` (state=`starting`), only `supervisor_alive` is checked. If a supervisor process lingers in memory (e.g., the Python interpreter is slow to exit after writing the final roster row), its `starting` row continues to subtract from `raw_spawn`. The birth debt formula reads:

```
spawnable = max(0, debt[p] - initializing[p])
```

So 4 stale `starting` entries can suppress 4 units of actual deficit. This is correct in intent, but the supervisor_alive guard uses `_process_generation_alive` which requires matching `proc_start_ticks`—a check that silently returns `False` (and thus skips counting) when the PID has been reused. PID reuse on Windows is slower than on Linux, but under load a lingering `starting` row from a supervisor that exited quickly (e.g., `spawn_failed`) may hold the PID that a new process immediately reuses, causing the `starting` row to be counted as alive even though the original supervisor is dead.

More critically: the v2 refill controller's design note says "initializing births reserve capacity but never clear debt (fail-visible until observed running)." This is correct but means that if a wave of 16 births all get stuck at `starting`/`initializing` (e.g., OpenCodex health check failing partway through), the full 16 initializing slots suppress further spawn attempts (`raw_spawn` goes to 0) while `running` stays at 0. Concurrency appears frozen at 0 effective even though the deficit is real.

### Finding 4 — Observer snapshot is the cross-plane authority but is silently disabled under four conditions

**Location:** `refill_controller_v2.py` → `_read_observer_snapshot()`, lines ~342–385

The 8765 observer is supposed to override local stale native roster counts. But it returns `None` (triggering fallback to local roster) when:

1. **Network unreachable** (`OSError` on `urlopen`) — observer process not running.
2. **Freshness >5 seconds** — observer has not updated recently.
3. **`freshness` not in `{"LIVE", "QUIET", "ESTIMATED"}`** — sets `observer_status = "stale"`.
4. **Root path mismatch** (`local not in advertised`) — sets `observer_status = "foreign_root"`.

When the observer is unavailable, the code falls back entirely to the local `native_roster.json`. The `cross_plane_observer` field in the refill state exposes this as `"unavailable"` or `"foreign_root"`, but no automatic recovery or alert escalates from this. Combined with Finding 1 (TTL-based stale rows), a 30-minute window of silent overcounting exists whenever the 8765 observer is not running.

### Finding 5 — `close_agent` is never called programmatically from the refill or lifecycle path

**Location:** All harness Python files

`grep` across all harness files finds `close_agent` mentioned only in:
- `lifecycle_supervisor.py` docstring (passive reference: "only the Codex host runtime can release those native slots")  
- `refill_controller.py` v1 `host_close_agent` field (a **recommendation** written to `refill_state.json`, not an invocation)

The v1 refill controller computed `host_close_agent: [list of agent_ids]` and set `host_close_agent_required: true` in state when idle/completed/shutdown_pending agents exceeded the `idle_reclaim_threshold`. This was read by the Sol orchestrator turn which was expected to call `close_agent` for each listed ID. **In v2 this entire v1 idle-reclaim path was removed.** `RefillControllerV2.recompute()` has no `host_close_agent` field—the fix for K3 starvation eliminated the demand-side idle-reclaim signal entirely.

The net effect: Desktop-native agents in `idle`, `completed`, or `shutdown_pending` state no longer trigger any automated close suggestion. The v2 controller counts only `running` agents toward effective concurrency (correct), but since `running` rows stay stale for up to 30 minutes (Finding 1), there is no mechanism to force slot release until TTL. This is the primary root cause of the concurrency decay described in the task.

### Root Cause Summary

| # | Where | What | Effect |
|---|-------|------|--------|
| 1 | `refill_controller_v2._read_roster_state()` | Native roster rows stay `running` for up to 1800s after Desktop agent terminates (no close_agent) | Deficit suppressed; refill_required stays False during the entire decay window |
| 2 | `desktop_edge_reconcile.apply_plan()` / lifecycle_supervisor | Desktop edge close is offline/manual; no automatic trigger exists | `open` edges persist, blocking host slot release even when agents are terminal |
| 3 | `refill_controller_v2.recompute()` spawn formula | Stale `starting` rows with liveness false-positive suppress `raw_spawn`; wave-stuck-at-initializing collapses refill | Deficit is present but computed as 0; concurrency frozen at initializing |
| 4 | `refill_controller_v2._read_observer_snapshot()` | Observer disabled under 4 failure modes with no auto-recovery | Falls back to stale local roster; Finding 1 goes undetected |
| 5 | v1→v2 refill controller migration | `host_close_agent_required` / `host_close_agent` signal was present in v1 and removed in v2 | Sol no longer receives a machine-readable list of agents to close; idle-reclaim path broken |

---

**Conclusion:** Concurrency decays post-terminal because completed Desktop-native agents are never automatically closed, their `running` rows persist for up to 30 minutes with no override, and the v2 refill controller removed the v1 `host_close_agent` signal that would have prompted Sol to call `close_agent`. The fix requires either (a) restoring a lightweight `host_close_agent` recommendation in the v2 refill state when TTL-stale or process-dead native rows are detected, or (b) shortening `NATIVE_RUNNING_TTL_SECONDS` and wiring an observer-fallback heartbeat so the 8765 snapshot stays within the 5-second freshness window even during quiet phases.
