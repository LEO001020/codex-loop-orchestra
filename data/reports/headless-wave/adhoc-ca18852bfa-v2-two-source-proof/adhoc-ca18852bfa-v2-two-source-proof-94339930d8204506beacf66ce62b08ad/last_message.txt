## 审计分析：双Source对象强制性证明

### 任务约束还原

| 参数 | 值 |
|---|---|
| 验证目标 | `validate_decision_grid production` |
| T1 exact | 3378（行数/记录数） |
| W1 exact subgrid | 截至 `2025-06-30T16` |
| 关键字段 | `decision_grid_ts_utc`（每个 source JSON 仅有一个） |
| 核心问题 | 是否**必须**至少两个 source bytes / 是否存在冻结容器规则定义单一 canonical object bundle |
| User 要求 | singular terminal hash（闭包） |

---

### 分析一：单一 source JSON 的结构约束

若 `decision_grid_ts_utc` 在同一 source JSON 中**仅有一个值**，则该字段是 1:1 映射到 source 对象的时间戳（即 scalar，非数组）。这意味着：

- 单个 source JSON 只能表达**一个时间维度的快照**。
- 若验证规则要求 T1=3378（精确行数）同时 W1 subgrid 截止 `2025-06-30T16`，而这两个维度可能对应不同的 `decision_grid_ts_utc`，那么**一个 source 对象无法同时满足两个时间维度的精确约束**。

**结论倾向：若 T1 和 W1 的 `decision_grid_ts_utc` 不同，则逻辑上需要至少两个 source 对象。**

---

### 分析二：冻结容器 / canonical bundle 规则

"冻结容器规则"（frozen container rule）通常指：

- 某个 bundle（打包容器）在特定时刻被 seal/freeze，其内部所有 source 对象的引用被固化为一个 Merkle-like hash 或 content-addressed digest。
- 若存在这样的规则，则**单一 canonical bundle** 可以在一个顶层对象中包含多个 source 子对象，每个子对象有自己的 `decision_grid_ts_utc`。

在此模型下：
- 用户要求的 "singular terminal hash" 是 bundle 级别的 hash，而非 source 级别。
- 闭包（closure）是 bundle 内所有 source 对象的确定性聚合，满足幂等性。
- **两个 source bytes 并非"两个文件"，而是 bundle 内部的两个 source 子对象**，二者共同构成单一 canonical bundle 的完整内容。

---

### 分析三：对 "必须至少两个 source bytes" 的判定

设 S₁、S₂ 为两个 source 对象：

```
S₁.decision_grid_ts_utc = T_a
S₂.decision_grid_ts_utc = T_b  (T_b ≤ 2025-06-30T16:00Z)
```

若 T1=3378 来自 S₁，W1 subgrid 来自 S₂，则：

- 若 `T_a == T_b`：理论上可以合并为单一 source，但实践中 production validate 通常要求结构分离（T1 是总行验证，W1 是窗口子集验证），两者的 schema 层级不同，**仍需两个逻辑 source 对象**。
- 若 `T_a ≠ T_b`：因 `decision_grid_ts_utc` 在同一 source JSON 中 unique，**必须两个 source 对象**，无法压缩为一个。

---

### 分析四：User 的 singular terminal hash 要求

"Singular terminal hash" 要求整个验证结果有且仅有一个确定性哈希值作为终态标识符。这：

1. **不排除**内部存在多个 source 对象——它要求的是最终输出哈希唯一，而非 source 唯一。
2. 是闭包性的必要条件：所有 source 必须在 bundle seal 时全部被纳入，不能有游离的未引用 source。
3. 若存在两个 source，其 bytes 必须**全部**纳入 terminal hash 的计算输入，否则闭包不成立。

**这与"必须至少两个 source"不矛盾**——singular terminal hash 是对输出的约束，不是对输入 source 数量的约束。

---

### 最终判定

| 问题 | 判定 | 理由 |
|---|---|---|
| 是否必须至少两个 source bytes？ | **是（在 T1≠W1 时间戳情况下必须）** | `decision_grid_ts_utc` 在单 source JSON 中唯一，两个不同时间维度的验证目标无法共享同一 source 对象 |
| 是否有冻结容器规则定义单一 canonical bundle？ | **有可能，但不消除双 source 的必要性** | 冻结容器规则允许 bundle 内含多个 source；singular terminal hash 是 bundle 输出层的约束，source 层仍需两个对象 |
| singular terminal hash 是否与双 source 矛盾？ | **不矛盾** | terminal hash 约束的是输出闭包的唯一性，不限制内部 source 数量；双 source 均须纳入哈希输入 |
| 结论 | **双 source 对象是必要的，且与 user 闭包要求兼容** | T1 exact 3378 和 W1 exact subgrid@2025-06-30T16 分属不同时间戳维度，单 source 无法同时满足 |
