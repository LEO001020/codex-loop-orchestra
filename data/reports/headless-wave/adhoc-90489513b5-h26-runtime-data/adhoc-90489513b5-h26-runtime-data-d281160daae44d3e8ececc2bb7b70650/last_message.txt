### LOCK AND TEMP FILES (process-owned, discard if owning process is dead)

| Pattern | Notes |
|---|---|
| `**/*.lock` | Advisory file locks — safe to remove when no live process holds them |
| `**/*.tmp.<pid>` (e.g. `exec_roster.json.38772.tmp`) | Atomic-rename temp files — orphaned if PID is not running; safe to delete |
| `data/orchestration/epilogue_status.json.tmp.36244` | Same: orphaned atomic-rename temp |

**Summary:** The 12 append-only NDJSON/JSONL event streams and per-packet write-once JSON files under `data/packets/`, `data/dead_letters/`, `data/sol_wake/`, `data/lifecycle_reports/`, and `data/repairs/` are immutable ledgers that must never be cleaned. Everything in the live-state group (rosters, refill state, provider health, metering snapshots, smoke artifacts, heartbeats, canary, hysteresis) is TTL-eligible once the owning process is idle or a configurable retention window (suggested: 7 days for dated ad-hoc artifacts, session-end for concurrency state). Lock and `.tmp.<pid>` files are process-owned and can be reaped whenever the owning PID is confirmed dead.
