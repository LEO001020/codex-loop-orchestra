## 普通模式隔离复核报告

### 一、快捷方式激活是 Desktop 全局时态模式，不是 per-workspace

**结论：已确认。**

`Set-Codex-LOOP-Mode.ps1 -Mode Activate` 调用 `global_desktop_mode.py activate`，该 action 做两件事：

1. **`install`**：将条件性钩子写入 `~/.codex/hooks.json`（全局用户级钩子），并将 `~/.codex/AGENTS.md` 替换为 `NEUTRAL_AGENTS` 边界提示文本。这些是 Codex Desktop **应用级**文件，对所有任务生效，与任务的 `cwd` 无关。
2. **`set_active(active=True)`**：写入 `E:\codex-LOOP\state\global-loop-mode.json`，`active=true`，`scope="all Desktop tasks regardless of target workspace"`。

在 `global_loop_mode.py` hook 侧，每次 `SessionStart`/`SubagentStart` 触发时，`load_active_marker()` 读取该 marker —— 这是**唯一决策点**，与当前任务的工作目录完全无关。

### 二、inactive 分支是安全无操作，不要求目标 workspace 存在 F2

**结论：已确认。**

`global_loop_mode.py` 的 `main()` 核心逻辑：

```python
if load_active_marker(root) is None:
    return 0          # ← inactive 分支：直接返回0，不执行任何操作
```

`load_active_marker` 返回 `None` 的所有情形：

| 情形 | 代码路径 |
|------|---------|
| marker 文件不存在 | `FileNotFoundError` → `return None` |
| 文件不可读/JSON解析失败 | `OSError/ValueError` → `stderr` 警告 + `return None` |
| `active != True`（含 `Deactivate` 后写入的 `active:false`） | `doc.get("active") is not True` → `return None` |
| schema 不匹配 | `doc.get("schema") != SCHEMA` → `return None` |
| `control_root` 路径不匹配 | `selected != _resolved(root)` → `stderr` 警告 + `return None` |

返回 `None` 后 `main()` 立即 `return 0`，不触发 `emit_context`，不触发 `dispatch`，不读取任何 F2 运行时文件，不检查目标 workspace 是否含有 F2。

### 三、Deactivate 与 Restore 的区别

`Deactivate` 仅修改 marker（`active: false`），钩子文件保持安装状态（下次 `Activate` 无需重新备份，幂等），但钩子代码因 inactive 分支直接返回 0 而成为无操作。

`Restore` 做完整回滚：
- 从 `global-loop-mode-install.json` 读取备份元数据
- 对每个文件校验 SHA-256 一致性（mismatch 则抛出异常，拒绝恢复损坏备份）
- 将 `AGENTS.md` 和 `hooks.json` 还原为安装前的精确字节
- 删除 marker 和 install state 文件
- 若文件安装前不存在，则直接 `unlink`（`missing_ok=True`）

### 四、普通模式不要求每个 workspace 存在 F2

`NEUTRAL_AGENTS`（安装时写入 `~/.codex/AGENTS.md`）明确写道：

> *LOOP behavior is selected by the machine-local Desktop mode launcher, not by the current repository name or working directory. When that context is absent, do not infer or apply LOOP concurrency, model-routing, packet, or harness rules merely because a previous task used LOOP or because a repository lives under `E:\codex-LOOP`.*

inactive 状态下，hook 不产生任何输出，agent 看不到 LOOP 工作协议注入，因此在任意 workspace（包括完全没有 F2 文件的目录）开始任务时，行为与纯普通 Desktop 任务完全相同。
