### 1. 两套独立计数器的设计

`loop_monitor_server.py` 维护了**两套彼此独立**的计数结构：

**① `pools` — 逻辑池标签**（`v4 / k3 / sol / other`）
- 通过 `pool_for(model, role)` 函数计算，依据运行时模型字符串 + 角色名做映射
- `weiwu/aws.claude-sonnet-4.6` 不匹配任何已知 pool 关键词（`k3 / deepseek-v4 / glm-5.2 / gpt-5.6-sol`），因此落入 `"other"` 桶
- 这是**容量管理**使用的逻辑分组，不是显示用模型名称

**② `model_counts` — 实际模型系列计数**（`v4 / sonnet / k3 / sol / other`）
- 通过 `model_family(row.get("model"))` 独立计算
- `model_family` 专门识别 `"claude-sonnet-4.6"` → 返回 `"sonnet"`
- 这是**显示面板**"实际运行模型"卡片使用的数据，绑定到 `d.models.sonnet`

### 2. sonnet46-all 下的具体行为

当前配置 `active_profile = "sonnet46-all"` 时：

- `review_model = "weiwu/aws.claude-sonnet-4.6"`

`model_family("weiwu/aws.claude-sonnet-4.6")` 的结果是 **`"sonnet"`**，正确地被计入 `model_counts["sonnet"]`，在前端显示为"Sonnet 4.6 **N**"。

### 3. 前端不会将 pool 标签直接当作显示模型

测试 `test_page_does_not_render_logical_pool_as_observed_model` 明确断言：
- `PAGE` 中存在 `function taskModel(x)` — 使用独立函数而非直接透传
- `PAGE` 中存在 `"审核池·模型待观测"` 和 `"执行池·模型待观测"` — 作为 **fallback 占位文字**，仅在 `x.model` 为空时显示
- `PAGE` 中**不存在** `"shortModel(x.model||x.pool)"` — 证明 pool 标签不会被当作模型名渲染

`taskModel(x)` 的逻辑：
1. 若 `x.model` 有值 → 调用 `shortModel(x.model)`（基于真实模型字符串映射）
2. 若无 model 且 pool 为 `k3` → 显示"审核池·模型待观测"
3. 若无 model 且 pool 为 `v4` → 显示"执行池·模型待观测"
