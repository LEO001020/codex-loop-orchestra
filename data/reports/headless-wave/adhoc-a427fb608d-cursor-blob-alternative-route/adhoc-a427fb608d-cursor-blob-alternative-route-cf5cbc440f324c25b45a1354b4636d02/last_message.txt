根据这份报告的内容，以下是针对 **OpenCodex 消费模型能力**这一目标，对 **Cursor OAuth 反向导出**路线与**官方兼容 API key / 其他 provider** 路线的四维对比分析：

---

## 稳定性

**官方兼容 API key 路线（路线一/二）**明显占优。报告指出，只要转发自己合法申请的 key，链路稳定性只取决于上游厂商的可用性，与 Cursor 客户端版本无关。轻量网关如 `gpt-load`、`nenya` 都是单二进制或简单容器，故障面极小。

**Cursor OAuth 反向导出路线（路线三中的逆向类）**——即 `cursor2api`、`composer-api`、`cursor-api-proxy` 这类——稳定性最弱。报告明说这类项目"追协议生意，Cursor 改客户端就可能崩，且变更不进发版说明"。实测数据佐证这一点：同类 16 个项目里 8 个近 90 天提交数 ≤10，7 个被判 slow/stale，逆向类的高提交量（如 `sub2api` c90=2212）恰恰是**不稳定的证据**，是被上游变更逼出来的追协议成本。

此外 Cursor 侧还有一个持续性问题：子 Agent 不继承 override，静默回退官方模型，官方明言暂无解——两条路线都承担这个 bug，但逆向路线额外叠加协议漂移风险。

---

## 成本

**官方兼容 API key 路线**：成本结构透明。直接付上游厂商 API 费用，Cursor Teams/Enterprise 用 BYOK 还要额外叠加 $0.25/百万 token 的 Cursor Token Rate。国内一方厂商（Kimi、GLM、MiniMax）提供官方兼容端点，价格更低，风险直接降到 low 档，是报告明确推荐的替代方向。

**Cursor OAuth 反向导出路线**：表面上"零 API 费"，实则风险溢价极高——触发封号后是"账号封禁 + 订阅作废 + 已付费用不退"三件同时发生，报告原话是"赌注远大于省下的钱"。对 OpenCodex 这种需要稳定消费模型能力的场景，这条路线的隐性成本更高，因为一旦封禁会中断整个工作流。

---

## 功能

两条路线在 Cursor 侧的**可用功能范围完全相同**，且都受同样的官方限制：

- Chat / 主 Agent 可走自定义端点（两条路线均可受益）
- Tab 补全、Cmd-K、Apply、Composer 系列、代码库 Embedding 均**无法走任何自定义路线**，任何中间层都帮不了这几项

官方兼容路线的额外优势在于，标准 OpenAI 兼容 + 专门为 Cursor 做 tool schema 归一化的网关（如 `api2cursor` 同时处理标准 `function` 与带 grammar `format` 的 `custom` 两种方言），Agent 工具调用成功率更高。逆向路线虽然偶有项目宣称覆盖更多功能（如 `leookun/cursor-byok` 声称 Chat/Agent/Tab 全覆盖），但代价是在系统根证书库写入公开 CA 私钥、Tab 流量默认经过作者服务器，报告明确列为"明确不推荐"。

---

## 风险

这是两条路线差距最显著的维度：

| 维度 | 官方兼容 API key 路线 | Cursor OAuth 反向导出路线 |
|---|---|---|
| ToS 风险档 | **low**（低风险，转发自己合法申请的 key） | **high**（用订阅登录态冒充官方客户端，32 个同类项目 31 个 high、0 个 low） |
| 账号安全 | 风险来自自己的部署配置，可控 | 直接面临封号 + 订阅作废 |
| 数据安全 | 自建链路下 prompt 只经过自己的服务器 | 逆向链路普遍依赖第三方组件，流量路径不透明 |
| 代码合规 | 有 LICENSE 的项目可正常部署交付 | 追协议项目普遍缺测试、缺 CI，供应链风险高 |
| 对 OpenCodex 的特殊影响 | 稳定可集成，key 可随时更换 | 协议一变整个消费能力当晚可能断掉 |

---

## 结论

对 OpenCodex 消费模型能力这一目标，**官方兼容 API key 路线**在稳定性、成本、功能、风险四个维度上全面优于 Cursor OAuth 反向导出路线。报告的核心判断是——换凭据来源（换成官方一方兼容端点）是唯一真正有效的降档手段，而订阅桥接/OAuth 反向导出这条路线"后果是封号+订阅作废+已付费用不退，三件事通常同时发生"。

具体落地建议对照报告：个人主力走 `gumieri/nenya` 或 `h88782481/api2cursor`，团队走 `QuantumNous/new-api`，国内厂商优先选 Kimi / GLM Coding Plan / MiniMax 官方兼容端点。逆向导出方案只适合在无价值独立账号上短期试验，不适合写进任何正式集成链路。
