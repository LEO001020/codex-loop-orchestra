## FL18 冻结 DB 模型 — 只读反证裁定（I4/I8）

### 一、research-writer 单写模型

**静态证据（S07、S08、S09、S26、S29）：**

- `S07_RESEARCH_WRITER_DB`：部署脚本中存在 `chown research-writer:research-writer` 和 `chmod 0600 /data/k3/research/research.sqlite`，确认 DB 文件归属服务用户，模式 0600，research-client 无读权限。
- `S08_RESEARCH_DIR`：目录为 `chown research-writer:research-client /data/k3/research`，模式 `0750`，普通 k3 进程无目录穿越权限。
- `S09_WAL_SHM_PERMS`：WAL/SHM 侧车文件所有权跟随服务用户（`research-writer:research-writer`），与主 DB 一致。
- `S26_INITIALIZE_DB_0600`：代码 `os.chmod(self.db_path, 0o600)` 和 `os.chmod(sidecar, 0o600)` 确保初始化时 DB/WAL 字节对 research-client 不可见。

**动态证据（T21、T22、T24）：**

- `T21_K3_DIRECT_DB_DENIED`：合成 k3 UID（uid=22003）对 0600 DB 的直接 `sqlite3.connect(mode=ro)` 调用必须失败（`returncode != 0`）。
- `T22_RESEARCH_WRITER_DAEMON_OPEN`：服务 UID（22001）打开 DB 并创建 Unix socket，对 k3/owner 两类身份实施中间层访问。
- `T24_SYNTHETIC_AUTHORITY_DAEMON_WRITE`：authority 表写入只通过服务 socket 完成，owner UID 凭证校验（`uid != owner_uid` → `PermissionError`）。

**结论（I4）**：research-writer 单写模型已被所有相关静态和动态测试覆盖，无任何反例。

### 二、DB/WAL/SHM 权限 0600、UMask 0077

**静态证据（S29、S26）：**

- `S29_DAEMON_UMASK_PRIVATE`：systemd 单元文件中 `UMask=0077`（守护进程新建文件默认为 0600），同时 `os.chmod(SOCKET, 0o660)` 确保 API socket 保持组可访问，两者协作。
- `S26_INITIALIZE_DB_0600`：`research_db.py` 中 `os.chmod(db_path, 0o600)` 和 `os.chmod(sidecar, 0o600)` 在初始化路径上强制设置。

**动态证据（T26）：**

- `T26_WAL_SHM_ROTATION`：fixture 以 `os.umask(0o077)` 启动服务进程，验证 WAL/SHM 创建后 `(stat.st_mode & 0o077) == 0`（即 group/other 位全为零），且数据在 rotate/reopen 后存活。

**结论（I4）**：DB/WAL/SHM 0600 与 UMask 0077 均有静态+动态双重固化证据，无反例。
