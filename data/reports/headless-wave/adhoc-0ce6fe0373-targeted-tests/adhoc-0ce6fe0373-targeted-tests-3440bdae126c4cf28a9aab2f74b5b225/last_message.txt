### 缺失的可隔离执行回归测试（按领域分类）

#### A. DB/WAL 层（research_db.py）

**I1 — WAL 模式强制与漂移检测**
- **缺失**：`ResearchDB.initialize()` 在 `journal_mode=WAL` 强制后若 PRAGMA 返回非 `wal` 应抛 `FailClosed("WAL unavailable: ...")`；重新 `_open()` 时若模式已漂移应抛 `FailClosed("journal mode drift: ...")`。
- 现有测试：`test_static_invariants.py` 只检查 `03_DEPLOY_APP_V3_AND_MIGRATE.sh` 文本中有 `"for s in -wal -shm"` 字符串，**未测试 Python 层 WAL 强制逻辑**。
- 可隔离运行：纯内存/tmpfs，无需生产 DB；使用 `RESEARCHCTL_ALLOW_TEST_FILESYSTEM=1`。

**I2 — synchronous=FULL 漂移检测**
- **缺失**：`_open()` 中 `synchronous != 2` 的 `FailClosed("synchronous drift: ...")` 分支未被测试。
- 可通过 monkey-patch PRAGMA 响应或直接在 tmpfs 测试 DB 上设置 `PRAGMA synchronous=0` 后重新 open 来隔离验证。

**I3 — 迁移维护锁原子性**
- **缺失**：`migrate()` 方法的 `maintenance_state` 进入/退出语义（进入 EXCLUSIVE 锁后崩溃 → 下次 `_short_write` 应收到 `MaintenanceActive`；成功迁移后 `active=0`）未被单元测试。
- 现有测试：`test_static_invariants` 仅检查脚本文字 `"app-v2 tree backup failed"`，未测试 Python `migrate()` 本身。

**I4 — 迁移禁止 IF NOT EXISTS**
- **缺失**：`migrate()` 的 `"IF NOT EXISTS"` 守卫（`FailClosed("migration scripts may not use IF NOT EXISTS")`）未被任何测试覆盖。

**I5 — backup_verify 完整性链**
- **缺失**：`backup_verify()` 的 `VACUUM INTO` 路径（source == backup == restore 逻辑一致性，probe 写入 + 重新打开验证）未被测试；`FailClosed("backup and restore targets must not exist")` 守卫也未覆盖。

#### B. TCB Exact-Set 安装（`03_DEPLOY_APP_V3_AND_MIGRATE.sh`）

**I6 — 精确集合安装 EXTRA/PYC 失败关闭**

- 需要：在沙箱目录中模拟安装场景（含额外文件），直接调用脚本或其等价 Python 逻辑，断言退出码非零。

**I7 — 安装后重新哈希（TOCTOU 关闭）**
- **缺失**：`f10_install_rehash` case（`"HASH-MISMATCH-INSTALLED" in DEPLOY`）只检查字符串存在，没有一个行为测试在源文件 swap 后验证脚本确实退出非零。

#### E. Identity（`authority_store.py` / `conditional_delegation.py`）

**I11 — `_owner_uid()` 与 `_owner_key()` 配置失败关闭**

- `direct_repair_stage` 的 `test_authority_store_v3.py` 通过 `monkeypatch` 覆盖了配置，但 FL18 自身无此测试。

**I12 — Ed25519 小阶点与非正则标量拒绝**

- 可完全隔离：不需要任何 DB 或文件系统。

**I13 — 会话分离（owner session ≠ producer session）**
- `direct_repair_stage` 有 `OWNER_SESSION_SEPARATION_FAILED` 测试，但 FL18 `tests/` 中**无等价测试**覆盖 `register_amendment_direct` 和 `transition` 两处的会话分离守卫。
