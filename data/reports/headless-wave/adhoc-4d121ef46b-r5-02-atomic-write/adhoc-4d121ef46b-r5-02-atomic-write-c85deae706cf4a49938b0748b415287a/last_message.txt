### P1：`orchestration_common.atomic_write_json` 缺少 Windows PermissionError 重试

**机械证据：**
- `lifecycle_supervisor.py` 第 84–118 行的注释明确写道：*"On Windows, antivirus/indexing and a reader without delete sharing can briefly make `os.replace` return `WinError 5`"*，并实现了 5 秒 / 指数退避重试逻辑。
- `orchestration_common.py` 第 278–288 行的 `atomic_write_json` **直接调用 `os.replace(tmp, path)`，无任何 `PermissionError` 捕获或重试**。
- 调用方（`refill_consumer_v2.py`、`layered_gate.py`、`plan_consumer.py`、`agent_router.py`、`budget_controller.py`、`dispatch_v2.py`、`recover_parent_replay_incident.py`）均未在调用侧捕获 `PermissionError`。
- 这意味着在 Windows 上，当反病毒软件或索引进程短暂持有目标 JSON 文件时，上述所有组件会抛出未捕获的异常，**导致状态写入失败，进程崩溃**。

**影响路径：** `orchestration_common.atomic_write_json` → `plan_consumer._finish` / `refill_consumer_v2` / `layered_gate` / `budget_controller` → 状态机写入静默丢失，LOOP 进入不一致状态。

---

### P1：`publish_report` 中裸 `os.replace`（`lifecycle_supervisor.py` 第 605 行）

**机械证据：** `publish_report` 函数（第 576–605 行）在写完 tmp 文件后直接调用 `os.replace(tmp, destination)`，没有 `PermissionError` 重试，而同文件第 84 行的 `atomic_json` 有完整重试逻辑。报告发布是关键路径（子代理完成时唯一的持久化操作），在 Windows 上 AV 扫描 tmp 文件时可导致 `WinError 5`，报告永久丢失，packet 状态无法推进。

---

### 不构成 P0/P1 的发现

- **`os.O_CREAT | os.O_EXCL` 原子性（`l2_consumer.py` 第 520 行）**：在 Windows 上 `os.open` with `O_CREAT | O_EXCL` 是原子的（通过 `CreateFileW` + `FILE_FLAG_NO_SHARING`），不存在竞态，**不是风险**。
- **`_append_line` 的 `os.mkdir` 锁（`l2_consumer.py` 第 337 行）**：`os.mkdir` 在 Windows 上是原子的，锁机制有效，**不是风险**。
- **`msvcrt.locking` 的锁实现**：`orchestration_common.file_lock` 在 Windows 上使用 `LK_LOCK`（阻塞），`lifecycle_supervisor.locked` 使用 `LK_NBLCK` + 带 timeout 的自旋；两者均正确，**不是风险**。
- **tmp 文件命名冲突**：`orchestration_common.atomic_write_json` 以 `{name}.{pid}.tmp` 命名，同目录两个进程 PID 相同时理论上可冲突，但 Windows 上 PID 不复用如此之快，**不构成实际 P1**。

### 汇总

| 风险 | 级别 | 文件:行 | 描述 |
|---|---|---|---|
| `orchestration_common.atomic_write_json` 无 Windows PermissionError 重试 | **P1** | `harness/orchestration_common.py:288` | 所有调用方（7 处）均无保护，Windows AV/indexer 短暂持锁 → 未捕获异常 → 状态丢失 |
| `publish_report` 裸 `os.replace` | **P1** | `harness/lifecycle_supervisor.py:605` | 报告发布路径无重试，Windows 上可永久丢失子代理报告 |

两项 P1 均来自同一根因：**修复路径在 `lifecycle_supervisor.atomic_json`（第 84 行）中已存在，但未被 `orchestration_common` 和 `publish_report` 采用**。修复方向是将重试逻辑提取到 `orchestration_common.atomic_write_json`，并在 `publish_report` 中复用，所有调用方无需更改。
