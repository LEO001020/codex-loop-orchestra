## 本地维护结论复核

### PASS — 上传云端前**不需要**实时 Codex 维护

**判断依据**

上传阶段本质上是一次静态资产交付：Fable 的内容（场景、角色、对话脚本等）已在本地完成编辑，上传操作本身是文件传输 + 云端构建流程，不涉及需要 Codex 实时介入的代码生成或逻辑决策。Codex 的职责域是代码编写/修改，而非部署管道监控。

### 最小必要本地服务清单

上传前需要保持运行的服务仅限于保证**数据完整性**和**传输通道**：

| 服务 | 作用 | 启动条件 |
|------|------|----------|
| 本地 Git / 版本控制客户端 | 确保上传的是最终提交版本，防止脏工作区混入 | 有未提交改动时必须先 commit |
| 网络连接（WSL2 / 宿主机代理） | 传输通道畅通 | 若用 VPN/代理需提前启动并验证可达性 |
| 目标云平台 CLI 或同步工具 | 实际执行上传（如 `rclone`、`rsync`、平台专属 CLI） | 凭据已配置且 token 未过期 |

**可选但推荐（降低风险）**

- 本地构建/预览服务（如 `vite dev` 或静态服务器）：在上传前做最后一次本地验证，确认无破损资产。上传完成后可立即停止，不需要持续运行。

---

### 启动顺序

1. 确认 Git 工作区干净（`git status` 无未提交文件）
2. 启动代理 / 确认网络可达目标云端
3. 执行 CLI 上传命令
4. 上传成功后，本地服务可全部停止

Codex 在整个流程中无需处于运行状态。若上传后需要根据云端反馈修改代码，届时再启动 Codex 处理即可。
