## 本地 E2E / 抓取通道在 A0–A16 各阶段的角色分析

以下"本地 E2E/抓取通道"指：Fable/k3 通过 SSH 或本地 CLI 直接读写 VPS 文件系统、执行命令的能力（即 Part 2.1 所描述的 Fable/k3 编排域）。

---

### 🟢 有用阶段（最早从 A0 开始）

| 阶段 | 操作 | E2E 通道作用 |
|---|---|---|
| **A0** | 新会话状态重建 | **最早有用点**。Fable 以只读方式连接 VPS，验证包哈希、Research Memory、权限状态、`/opt/p5`、authority 等。这是整条链路的基础前提。 |
| **A5** | 新鲜 k3 PRETRUST 负向证明（script 05） | Fable 通过新鲜 k3 登录执行只读 script 05，生成并保存 proof JSON + SHA。 |
| **A6** | Owner TCB 签名请求协调 | Fable 作为**只读协调者**重新哈希 TCB manifest，生成人类可读的签名请求，然后等待。k3 通道用于读取规范字节。 |
| **A8** | 部署后管理员验证（coordinator角色） | 视 current script 允许范围，Fable 可读取验证结果（不变更状态）。 |
| **A9** | 新鲜 k3 最终验证（script 08） | 与 A5 同理，Fable 通过新鲜 k3 执行只读负向证明。 |
| **A13–A16** | 后 root 委托执行（A/B/T1/W1/H0） | 这是 Fable/k3 通道**完整授权执行**的阶段。通过注册的 authority 走规范 CLI 执行所有 trial 操作，读取真实 P3 标签，运行 H0 景观生成。 |

---

### ⚪ 无关阶段（通道存在但不参与核心动作）

| 阶段 | 原因 |
|---|---|
| **A1** | Fable 只做是/否判断（是否存在独立管理员通道），不执行任何 VPS 动作。 |
| **A3**（结果核实） | 实际 cutover 动作由独立管理员执行；Fable 事后读取 receipt 是被动验证，不是主动 E2E 步骤。 |
| **A10/A11（C/D协调）** | Fable 只是协调者，展示 payload hash，等待 owner 意图；`owner_ceremony.py` 的实际执行须由 human owner 直接发出，不是由 Fable E2E 通道驱动的。 |

---

### 🔴 违反 trust-domain 的场景（通道存在但**使用即违规**）

| 阶段 | 违规行为 | 原因 |
|---|---|---|
| **A2** (order 02) | Fable 通过 k3-sudo 执行管理员恢复脚本 | `sudo` from k3 **不等于**独立 root；script 02 明确拒绝通过 k3 sudo 获得的 root shell。 |
| **A3** (order 03) | Fable 通过 k3 执行 deprivilege / 清除 SUDO_USER | 这是反洗用（anti-laundering）规则明确禁止的场景，清除环境标记以绕过 `assert_executor_is_not_agent` 是 hard-fail 行为。 |
| **A4** (order 04) | Fable 通过 k3 触发 reboot | 必须是独立管理员/root 通道；k3 发起的 reboot 无法满足"新鲜 post-reboot k3 登录"的隔离要求。 |
| **A6–A7 之间** | Fable 代为生成 owner 私钥或 TCB 签名 | owner 私钥永远不离开 owner 设备；Fable 传输 detached signature 可以，**持有或生成私钥绝对不行**。 |
| **A10/A11** | Fable 捏造 `HUMAN_OWNER_SIGNED` 或直接执行 C/D | C/D 须是 human owner **直接**通过 `owner_ceremony.py` 发起，自然语言"同意"不等于加密签名。 |
| **A12** | Fable 自签 root V6 payload | root 签名必须是 owner 离线签名后回传 detached signature，Fable 只能附加+验证，不能签署。 |
| **A13 之前访问真实 P3 标签** | 任何在 T1 APPLIED 之前读取/派生真实 P3 outcome 的 E2E 操作 | 科学信息顺序规则（§0.6）明确：T1 APPLIED 是第一个允许访问真实标签的时间点，早于此的任何抓取都违反 trust-domain。 |

---

### 核心结论

```
最早有用：A0（只读状态重建，整条链路的锚点）
完整授权执行：A13–A16（post-root 委托阶段，k3 通道是唯一执行者）
无关过渡带：A1、A3结果验证、A10/A11协调等待
违规红线：
  - A2/A3/A4 用 k3-sudo 冒充独立管理员
  - A6/A10/A11/A12 代持/代签 owner 私钥或伪造 owner 意图
  - A13 之前任何真实 P3 标签抓取
```
