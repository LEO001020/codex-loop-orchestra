### 问题二：canonical symbol key是否唯一确定？

**是，canonical key唯一固定。**

Source schema（`load_source`函数）的关键行为：
```python
symbols = source.get("symbols")
if not isinstance(symbols, dict) or not symbols:
    raise FailClosed("PC6_SOURCE_SYMBOLS_INVALID")
```

后续 `derive_features` 和 `derive_outcomes` 均使用：
```python
symbols = sorted(source["symbols"])
```

这意味着：
1. Source对象的 `symbols` 是一个Python dict，其**键（key）即为canonical symbol标识符**。
2. 该key从manifest中的 `symbol` 字段继承，与身份映射中的 `perp_symbol` / `futures_pair` 字段一一对应。
3. 代码层不对key做任何转换或重映射，字典序排序是唯一后续操作。

**关键约束**：source schema允许任意非空的symbols字典——即**输入方可以提交任意符号子集**。代码不检查symbols键是否存在于manifest；PIT universe rule的filtering（`P5_P3_PIT_UNIVERSE_EXECUTION_RULE_V1#POST_DECISION_LABEL_MISSINGNESS_RULE`）在evaluator层按decision-time数据可用性隐式过滤，而非在load_source层强制拦截。

### 问题三：listing-episode处理是否唯一确定？

**是，处理规则唯一确定，但属于passthrough模式。**

`P5_P3_LISTING_EPISODE_LEDGER_V1.json` 记录每个符号的：
- `pit_eligibility_conservative_start_us`：PIT保守边界（基于最早有数据的原始时间，而非挂牌元数据时间）
- `earliest_candidate_listing_us`：元数据挂牌时间（可能与真实数据边界不一致，故标注 `disagreement_state: SOURCE_DISAGREEMENT`）

Listing episode账本**并非由source schema或load_source直接消费**——它作为frozen scientific binding的一部分通过 `perp_spot_identity_map_sha256`（SHA-256绑定）和 `listing_episode_ledger_sha256` 在enumerator `COMMON.PC6` 字典中哈希绑定，验证由precondition PC3（`PREREG_ESTIMAND_AND_PIT_BINDINGS`）确保。

实际的listing边界在feature derivation中**以数据可用性隐式执行**：`_snapshot()` 在时间戳 `t` 无可用bar时返回 `None`，对应符号在该cohort被排除。`pit_eligibility_conservative_start_us` 是外部分析层面的参照，而非materializer内的直接过滤条件。

**每个符号只有一个listing episode**（`relisting_evidence: NO_SEPARATE_EPISODE_PROVEN`），不存在多episode的歧义处理问题。
