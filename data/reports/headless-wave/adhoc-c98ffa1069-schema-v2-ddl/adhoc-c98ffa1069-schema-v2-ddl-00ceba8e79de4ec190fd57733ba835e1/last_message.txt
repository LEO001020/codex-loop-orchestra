## 2. authority 相关表与约束提取

| 表 | PK / UNIQUE | FK（全部 RESTRICT/NO ACTION，无 CASCADE） | 关键 CHECK |
|---|---|---|---|
| authority_proposals | PK `proposal_id`；UNIQUE `(run_id, binding_sha256)` | — | `run_class='STATISTICAL_TRIAL'`、`binding_sha256`/`binding_json` 合法 |
| authority_transitions | PK `transition_id` AUTOINCREMENT；UNIQUE `event_sha256`、UNIQUE `(proposal_id, daemon_ledger_sequence)` | `proposal_id → authority_proposals` | `from_state∈{NONE,PROPOSED,PRECONDITIONS_PASS,HUMAN_OWNER_SIGNED}`、`to_state∈{PROPOSED,PRECONDITIONS_PASS,HUMAN_OWNER_SIGNED,APPLIED}`、`event_sha256` 64 hex |
| logical_trials | PK `logical_trial_id`；UNIQUE `grant_proposal_id`（= ONE_AUTHORIZED_WAVE_PER_GRANT） | `grant_proposal_id → authority_proposals` | `candidate_list_sha256` 64 hex |
| trial_attempts | PK `attempt_id`；UNIQUE `(logical_trial_id, attempt_ordinal)` | `logical_trial_id → logical_trials` | `attempt_ordinal>=1`、`state∈{RUNNING,ATTEMPT_VOID,COMPLETED}`、`checkpoint_sha256` 可空 64 hex |
| owner_conditional_delegations | PK `delegation_id` | — | `owner_credential_scheme='ED25519'`、`state∈{ACTIVE,OWNER_DELEGATION_REVOKED}`、签名/scope hash 64 hex |
| owner_delegation_revocations | PK `revocation_event_id`；UNIQUE `delegation_id`（每条 delegation 至多一次 revoke） | `delegation_id → owner_conditional_delegations` | — |
| delegation_redemptions | PK `redemption_event_id`；UNIQUE `(delegation_id, child_proposal_id)`（每 delegation-child 至多一次 redeem） | `delegation_id → owner_conditional_delegations`；`child_proposal_id → authority_proposals`；`preconditions_transition_id`/`human_owner_signed_transition_id → authority_transitions` | `scope_sha256` 64 hex |
| amendment_registrations | PK `amendment_event_id`；UNIQUE `amendment_id`、UNIQUE `registration_ordinal` | `delegation_id → owner_conditional_delegations` | `amendment_id∈{C,A,B}`、`registration_ordinal BETWEEN 1 AND 3`、`authorization_mode∈{INTERACTIVE_OWNER_SIGN,PREAUTHORIZED_CONDITIONAL_DELEGATION}` |

关联基表：`audit_events`（UNIQUE `event_key`、`event_hash`、`(entity_type,entity_id,entity_revision)`；`previous_event_hash` 链；`owner_id=actor_owner_id`）、`migration_audit`（PK `migration_id`；`to_version=from_version+1`；pre/post `integrity='ok'`）、`agent_runs`（v3 将改 CHECK）。

## 3. Trigger 清单

| Trigger | 表 | 语义 |
|---|---|---|
| delegation_no_update / delegation_no_delete | owner_conditional_delegations | 行不可变；撤销只能通过 revocation 事件 |
| delegation_revocation_no_update / delegation_revocation_no_delete | owner_delegation_revocations | 撤销事件 append-only |
| amendment_no_update / amendment_no_delete | amendment_registrations | 注册 append-only |
| authority_transition_order（BEFORE INSERT） | authority_transitions | FSM：NONE→PROPOSED→PRECONDITIONS_PASS→HUMAN_OWNER_SIGNED→APPLIED，非法迁移 ABORT |
| authority_transitions_no_update / authority_transitions_no_delete | authority_transitions | 迁移账本 append-only |
| logical_trials_no_update / logical_trials_no_delete | logical_trials | 试验声明不可变 |
| audit_events_no_update / audit_events_no_delete | audit_events | 审计链 append-only |
| migration_audit_no_update / migration_audit_no_delete | migration_audit | 迁移审计 append-only |

**已确认缺口**（fsm 报告 §5 C2/C3 建议但未进入 shipped v2）：`authority_proposals`、`delegation_redemptions`、`trial_attempts` 无 no-update/no-delete trigger；`authority_transitions` 无 `previous_event_sha256` 链式 trigger、`daemon_ledger_sequence` 仅 per-proposal UNIQUE；`amendment_registrations` 的 C→A→B 顺序只由 `register_amendment()` 代码强制（`C_A_B_ORDER_VIOLATION`）。

## 4. v3 迁移必须保持的 append-only 不变量

1. **审计链不可变**：`audit_events` 保持 no-update/no-delete；`event_key`、`event_hash` 唯一；`(entity_type,entity_id,entity_revision)` 修订链唯一；`previous_event_hash` 首行 NULL、后续等于前一行 `event_hash`。重建表以放宽 workload/authority CHECK 时，不得改变列语义、不得改写任何既有行。
2. **迁移审计不可变**：`migration_audit` 保持 no-update/no-delete；`migration_id` 幂等防重放；`to_version=from_version+1`；pre/post 备份 + `integrity='ok'` 硬约束继续成立。
3. **提案幂等且不可变**：`authority_proposals` 的 `(run_id, binding_sha256)` 唯一保持；v3 重建时应补 no-update/no-delete trigger（当前仅靠代码无写路径）。
4. **迁移账本链式**：`authority_transitions` 保持 no-update/no-delete 与 FSM 顺序 trigger；`event_sha256` 唯一；建议 v3 补全局 `daemon_ledger_sequence` 唯一 + `previous_event_sha256` 链 trigger（fsm C2），否则断链只能靠只读 `verify_authority()` 兜底。
5. **委派不可变、撤销只增**：`owner_conditional_delegations` 保持 no-update/no-delete，状态只能经 `owner_delegation_revocations` 事件转为 REVOKED；revoke 后 redeem/amendment 必须继续被拒。
6. **撤销至多一次**：`owner_delegation_revocations` append-only 且 `UNIQUE(delegation_id)`。
7. **Amendment 只注册一次、顺序固定**：`amendment_registrations` append-only；`UNIQUE(amendment_id)`、`UNIQUE(registration_ordinal)`；C→A→B 顺序在 v3 应升级为 DB trigger（fsm C3），不能降级为纯内存校验。
8. **每 grant 至多一个试验**：`logical_trials` 不可变且 `UNIQUE(grant_proposal_id)`（ONE_AUTHORIZED_WAVE_PER_GRANT）。
9. **Attempt 序列只增**：`trial_attempts` 行允许状态机推进（RUNNING→ATTEMPT_VOID/COMPLETED），但 `(logical_trial_id, attempt_ordinal)` 唯一、序号单调递增，历史 attempt 不得删除。
10. **Redemption 至多一次**：`delegation_redemptions` 保持 `UNIQUE(delegation_id, child_proposal_id)` 与 3 条 FK；v3 建议补 no-update/no-delete trigger。
11. **FK 一律 RESTRICT/NO ACTION**：v3 重建任何表都不得引入 ON DELETE CASCADE；父行删除必须被物理阻断。
12. **禁止回滚补写**：若 v3 失败，只允许 forward-repair（新 migration_id 重跑），不得“回滚旧备份再补写新事件”——authority 表带 no-update/no-delete trigger、审计链带哈希校验，补写必然断链（migration-ops 硬规则）。

另：8 张 authority 表当前全空，v3 重建无数据迁移负担，但 schema 语义（trigger/UNIQUE/FK）必须逐条保持，且迁移仍须走 `BEGIN EXCLUSIVE` + pre/post `VACUUM INTO` 备份 + integrity 校验 + `migration_audit` 落账的既有路径。
