基于对 `E:\Program Files\ZCode` 插件目录和 `E:\codex-LOOP\codex-loop-s-f2` LOOP 运行环境的核验，MCP 配置在 ZCode 中的安装语义如下：

### 1. MCP 配置形状 (Shape)
插件的 MCP 定义位于各插件目录下的 `.mcp.json` 文件中，其结构符合标准的 MCP 服务器配置规范。

- **根节点**: `"mcpServers"` 对象。
- **配置项**: 服务器名称作为键，其值是一个包含 `command` (通常为 `"node"`)、`args` (路径使用 `${CLAUDE_PLUGIN_ROOT}` 或 `${ZCODE_PLUGIN_ROOT}` 变量)、`cwd` (通常为 `${ZCODE_PROJECT_DIR}`) 以及 `env` (环境变量映射) 的对象。
- **变量**: 使用 `${}` 语法引用插件根目录、数据目录等动态路径变量。

### 2. stdio/http 支持
基于 `android-emulator` 插件的 `.mcp.json` 配置查看，该环境下主要通过 `stdio` 方式运行 MCP 服务器（通过直接调用 `node` 执行插件目录下的 `server.js`）。未发现明确的 `http` 协议配置。

### 3. 插件根变量 (Plugin Root Variables)
插件配置使用明确的平台变量进行路径注入，以实现通用性：
- `${ZCODE_PLUGIN_ROOT}` / `${CLAUDE_PLUGIN_ROOT}`: 指向插件安装的根目录。
- `${ZCODE_PROJECT_DIR}` / `${CLAUDE_PROJECT_DIR}`: 指向插件的运行工作目录。
- `${ZCODE_PLUGIN_DATA}` / `${CLAUDE_PLUGIN_DATA}`: 指向插件的数据存储路径。
- `user_config.*`: 从 `.zcode-plugin/plugin.json` 中的 `userConfig` 定义动态解析用户配置。

### 4. 继承或隔离语义
- **隔离性**: 插件通过其独立的 `.mcp.json` 定义实现 MCP 服务器层面的逻辑隔离。它们被装载为独立的进程，利用各自的运行环境 (`env` 中的专有变量) 进行隔离。
- **继承性**: LOOP 运行环境与 ZCode 插件目录结构在文件系统上是独立的。LOOP 环境通过 `hooks` 机制（如 `global_hooks.json`）管理全局行为，但插件配置本身遵循各自的配置文件 (declarative)，通过插件管理工具注入到运行环境中，并不直接继承根环境的 MCP 配置。

此安装语义确保了插件配置的可移植性与运行时的隔离。
