现在我有了完整的证据，可以做出明确的判断。

## 双Hook边界复核报告

**结论：在当前 `cold_start` 模式下，重复 Sol gate hook 对 Sonnet 子代理是有害的（会误拒），而非无害。**

---

### 1. 当前活跃的 Hook 配置

当前会话实际生效的 hooks.json（`user_hooks_normalized_current.json`）：
- **PreToolUse** 中只有一条 hook：`leaf_agent_spawn_gate.py`（匹配 `spawn_agent|create_thread|fork_thread`，用于阻止 leaf agent 递归孵化）
- **没有** `sol_tool_gate_router.py` 的 PreToolUse 条目

而 `hooks.json.example` 中声明了两条 PreToolUse hook（router + lifecycle），但这只是示例文件，**不是当前活跃配置**。

---

### 2. 如果两条 Sol gate hook 同时生效（示例配置被激活），在 cold_start 下的行为

`sol_tool_gate_router.py` 在 `cold_start` 模式下委托给 `sol_tool_gate.py`（v1）。

**v1 gate 的 MODEL_FAMILY 硬编码如下：**

```python
MODEL_FAMILY = {
    "gpt-5.6-sol": "sol",
    "gpt-5.6": "sol",
    "alibaba-token-plan/glm-5.2": "v4",
    "weiwu/glm-5.2": "v4",
    "weiwu/deepseek-v4-flash": "v4",
    "weiwu-k3/kimi-k3": "k3",
}
```

**但当前 policy（`orchestration_policy_v2.toml`）中 Sonnet 子代理的实际 model 标识为：**

```toml
k3_model = "weiwu/aws.claude-sonnet-4.6"
v4_model = "weiwu/aws.claude-sonnet-4.6"
```

`weiwu/aws.claude-sonnet-4.6` **不在 v1 gate 的 MODEL_FAMILY 中**。

---

### 3. Sonnet 子代理发起 gated 工具调用时的执行路径

v1 gate 的判断逻辑：

```python
family = MODEL_FAMILY.get(model)   # → None（Sonnet 不在表中）
if family in ("v4", "k3"):
    return 0                       # 放行 —— 不命中
if family != "sol":                # None != "sol" → True
    # DENY，原因：model 未知，无法识别身份
```

**结论：cold_start 下，如果 sol_tool_gate_router 挂载生效，Sonnet 子代理（无论是 k3 还是 v4 角色）调用任何 gated 工具都会被 v1 gate 以"model 未知"为由拒绝。**

---

### 4. 当前实际状态：无害

当前活跃的 hooks 配置（`user_hooks_normalized_current.json`）中 **PreToolUse 没有挂载 sol_tool_gate_router**，只有 leaf spawn gate。因此：

- 当前 cold_start + 当前 hooks → **Sonnet 子代理不受 Sol gate 影响，无误拒风险**
- `hooks.json.example` 中的双 hook 是待部署示例，尚未激活

---

### 5. 风险边界

| 场景 | 是否有害 |
|---|---|
| 当前实际 hooks（仅 leaf gate）+ cold_start | ✅ 无害，Sonnet 子代理不受影响 |
| 若激活 hooks.json.example（双 PreToolUse hook）+ cold_start + Sonnet 作为 k3/v4 | ❌ **有害**：v1 gate 硬编码表缺少 `weiwu/aws.claude-sonnet-4.6`，会以"unknown model"路径 deny |
| layered 模式下激活双 hook | ❌ 有害（但与 cold_start 无关） |

---

### 6. 根因定位

v1 gate（`sol_tool_gate.py`）的 MODEL_FAMILY 表在 provider 切换到 Sonnet 后**未同步更新**，这是 `hooks-policy-entry-audit-20260812/report.md` 第 1.3 节已记录的"hardcoded model table vs policy model pins"分裂问题（D3 类别）。

**当前 cold_start 模式下是安全的，原因是 sol_tool_gate_router 未挂载于当前活跃 hooks 配置，而非 v1 gate 本身兼容 Sonnet。** 若 hooks 配置被切换为 example 版本，Sonnet 子代理将受到误拒。建议在激活 router hook 前，同步更新 v1 gate 的 MODEL_FAMILY 或改为从 policy 动态读取 model 列表。
