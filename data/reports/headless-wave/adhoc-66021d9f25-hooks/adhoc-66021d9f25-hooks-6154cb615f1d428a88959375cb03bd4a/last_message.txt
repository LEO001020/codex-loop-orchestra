本次只读核验基于 `E:\codex-LOOP\codex-loop-s-f2` 环境（LOOP_CONTROL_ROOT）的 Hook 机制。

### 1. Hook 宿主与事件契约 (PreToolUse)
核心 Hook 为 `hooks/sol_tool_gate.py`，它作为 `PreToolUse` 的机械门控，强制执行 Sol 纪律。
- **作用机制**：当 `LOOP` 状态非 planning/adjudication/release_finalize 时，若 `root` (Sol) 尝试调用 shell、搜索、批量读文件、测试或统计工具，门控将 DENY 该调用，并提示将任务委派为 `L0/L1` packet。
- **Matcher (规则匹配)**：
  - `GATED_TOOLS`：枚举了所有受限工具（shell*, exec_command, search, read_*, test 等）。
  - `role` 检查：如果属于 `CHILD_ROLES` (`worker`, `verifier` 等)，则直接放行 (return 0)。
  - `LOOP` 状态机：通过 `progress_ledger.json` 中的 `loop_state` 字段（若无则从 `packets` 状态推导）进行决策。

### 2. Events 契约 (stdin/stdout/exit code)
通过对 `data/events.ndjson` 的结构抽样分析（数据结构遵循 NDJSON）：
- **stdin 字段**：各 `PreToolUse` 或 `spawn` 事件通常包含完整的 `tool_name`、`args` 及工作上下文 (`cwd`)。
- **stdout JSON**：当 Hook 拒绝调用时，输出格式严格为 `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", ...}}`。
- **退出码**：Hook 脚本通常以 `exit 0` 与空输出（stdout/stderr 结合）表示允许；以 `exit 0` 与格式化的 deny JSON 表示拒绝。

### 3. SessionStart 与 生命周期事件
- **SessionStart**: 启动、恢复 (resume)、清理 (clear)、压缩 (compact) 等事件记录于 `data/events.ndjson`，并由 `data/progress_ledger.json` 的主状态机驱动。
- **SessionStart**: 系统通过 ledger 中的 `loop_state` 维护关键生命周期状态。
- **Compact**: 策略要求删除内容保留路径，summary 必须包含 report index 和校验清单（由 `recoverable compression` 约束）。

### 4. PostToolUse 观察
- 与 `PreToolUse` 不同，PostToolUse 的 Agent 行为观察主要通过 harness 层的 `lifecycle_supervisor.py` 和对 `exec_roster.json` 的监控来实现。
- 门控 Hook `sol_tool_gate.py` 没有显式的 PostToolUse 执行权。调用行为审计由基础设施 (`data/events.ndjson`) 记录，供外部 `run_view.py` 和 `run_evidence.py` 分析。

**结论**：HOOK 契约的安全性由 `sol_tool_gate.py` 的 PreToolUse 层级强制执行。所有 `root` 层的非计划性操作均被强制重定向至 Worker/Verifier Packet 接口。无需额外动作。
