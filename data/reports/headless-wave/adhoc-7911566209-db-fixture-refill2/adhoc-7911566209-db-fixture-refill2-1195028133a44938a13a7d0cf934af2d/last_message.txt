### 1. Distinct UID DB 0600 — T21

**设计意图**：DB 文件权限 0600，`service_uid=22001` 为所有者，`k3_uid=22003` 持有 `shared_gid=22002` 但不是 service_uid，因此直接 `open` 应被拒绝。

**夹具代码**：
```python
os.chown(db, service_uid, service_uid); os.chmod(db, 0o600)
```
k3 进程以 `uid=22003, gid=22002` 运行，尝试直接以只读 URI 打开。

**发现**：✅ 正确。`0o600` + `chown(service_uid, service_uid)` 确保 k3_uid 既非所有者又不在所有者 gid，访问被拒绝。没有问题。

### 2. Service Daemon (T22) — 内联 `server_py` 写法

**发现：⚠️ 轻度问题（不影响功能，但有隐患）**

```python
server_py.write_text('''import json,os,socket,s sqlite3,struct,sys\n'''.replace('s sqlite3','sqlite3') + ...
```

这段用 `.replace('s sqlite3','sqlite3')` 在运行时修正字符串，是一种**刻意混淆**写法——目的是避免 CI 代码扫描器把 `import sqlite3` 识别为直接 DB 访问。写法本身执行后是正确的（`import json,os,socket,sqlite3,struct,sys`），但：

- 可维护性差：未来对该行的任何修改都可能意外破坏 replace 逻辑
- 若 `.replace` 被静默移除，`s sqlite3` 会导致 `SyntaxError` 并让 T22–T26 全部失败

**最小修正建议**（只改混淆写法，不改逻辑）：
```python
server_py.write_text(
    'import json,os,socket,sqlite3,struct,sys\n' + '''
db,sock,owner_uid=...
```
即直接写完整 import，移除 replace 技巧。

### 3. WAL/SHM 权限 — T26

**设计意图**：WAL 进程以 `service_uid=22001` 运行，umask=0o077，确保 `-wal` 和 `-shm` 文件的 `other/group bits` 全为 0（即 `mode & 0o077 == 0`）。

**发现：⚠️ 轻度缺陷 — preexec_fn 的 GID 设置不一致**

WAL 子进程的 `preexec_fn`：
```python
preexec_fn=lambda: (os.umask(0o077), os.setgroups([service_uid]), os.setgid(service_uid), os.setuid(service_uid))
```

注意 `os.setgroups([service_uid])` 把 **service_uid（22001）当成了 GID** 传入，而不是 `service_gid`。在其他 daemon 启动中用的是 `shared_gid=22002`：
```python
preexec_fn=lambda: (os.umask(0o077), os.setgroups([shared_gid]), os.setgid(shared_gid), os.setuid(service_uid))
```

WAL 探针进程以 `gid=service_uid(22001)` 运行，而 DB 文件的所有组是 `service_uid(22001)`（因为 `os.chown(db, service_uid, service_uid)`），所以实际上**碰巧能工作**，但语义是"把 UID 当 GID 用"，与 DB 目录 `chown(service_uid, shared_gid)` 的意图不一致。

这是一处 UID/GID 混用，在真实环境中 service_uid ≠ service_gid 时会导致 WAL 文件以错误 gid 创建，可能让权限检查出现误报或漏报。

**最小修正建议**：为 WAL 子进程单独定义 `service_gid`，或将 WAL 探针的 preexec_fn 改为与 daemon 一致：
```python
preexec_fn=lambda: (os.umask(0o077), os.setgroups([shared_gid]), os.setgid(shared_gid), os.setuid(service_uid))
```
