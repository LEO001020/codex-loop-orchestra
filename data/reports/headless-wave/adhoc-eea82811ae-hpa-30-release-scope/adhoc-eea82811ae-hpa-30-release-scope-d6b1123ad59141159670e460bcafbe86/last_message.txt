### Blocker（必须修复，否则文档误导用户）

**1. `packages/coding-agent/docs/providers.md` — providers 表缺 `moonshotai` / `moonshotai-cn`**

证据：
- `packages/ai/src/env-api-keys.ts` 明确定义 `moonshotai → MOONSHOT_API_KEY`，`moonshotai-cn → MOONSHOT_API_KEY`
- `packages/ai/src/types.ts` 的 `KnownProvider` 包含 `moonshotai` 和 `moonshotai-cn`
- `packages/coding-agent/src/core/provider-display-names.ts` 有 `moonshotai: "Moonshot AI"`, `"moonshotai-cn": "Moonshot AI (China)"`
- `packages/coding-agent/src/core/model-resolver.ts` 有 `moonshotai: "kimi-k2.6"`, `"moonshotai-cn": "kimi-k2.6"` 默认模型
- providers.md 表中完全没有这两行；用户无法通过文档得知 `MOONSHOT_API_KEY` env var 或 `moonshotai` auth key
- `packages/ai/CHANGELOG.md` 记载：「Added Moonshot AI as a built-in OpenAI-compatible provider...」—— 功能已发布，文档未跟进

缺失行（参照现有格式）：
```
| Moonshot AI | `MOONSHOT_API_KEY` | `moonshotai` |
| Moonshot AI (China) | `MOONSHOT_API_KEY` | `moonshotai-cn` |
```
需加在 MiniMax (China) 行之后或 Xiaomi 系列之前（与 `env-api-keys.ts` 中的顺序对齐）。

**2. `packages/coding-agent/README.md` — API keys 列表缺 `Moonshot AI` 和 `Moonshot AI (China)`**

证据：第 78–103 行的「API keys:」列表包含 ZAI、OpenCode Zen/Go、Hugging Face、Fireworks、Kimi For Coding、MiniMax、Xiaomi 系列，但无 Moonshot AI 两项。用户在 README 无法发现该提供商存在。

缺失项：
```
- Moonshot AI
- Moonshot AI (China)
```
位置：MiniMax 之后、Xiaomi 之前（与 providers.md 表顺序一致）。

证据：
- Supported Providers 列表（~第 63–87 行）：没有 Moonshot AI（直连提供商）和 Hugging Face；仅有「Kimi For Coding (Moonshot AI, ...)」

- `moonshotai` / `MOONSHOT_API_KEY` → `env-api-keys.ts` + `KnownProvider`
- `minimax-cn` / `MINIMAX_CN_API_KEY` → `env-api-keys.ts` + `KnownProvider`
- `huggingface` / `HF_TOKEN` → `env-api-keys.ts` + `KnownProvider`

这是 library README，次于 user-facing 的 coding-agent docs，但同样是公开文档，属于 **required** 修复。
