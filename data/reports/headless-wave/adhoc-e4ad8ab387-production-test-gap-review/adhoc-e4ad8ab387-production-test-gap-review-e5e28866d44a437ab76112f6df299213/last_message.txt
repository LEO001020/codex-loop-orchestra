### 问题重构

根据描述，有两个相互关联的测试缺口：

**缺口 A — 合成模式绕过生产清单校验**

冻结测试（frozen tests）在 `P5_SYNTHETIC_MODE=1` 且 `consumed_non_outcome_objects=[]` 时创建 source plan。这意味着：

- 结果：一个在生产环境中实际上"不可满足"（unsatisfiable）的计划，在测试中却以 PASS 通过

这意味着这个前提条件（precondition）从未在任何测试场景中被触发或断言。

### 合成 PASS 如何掩盖生产不可满足性

以下是完整的掩盖链：

```
测试路径                         生产路径
──────────────────────────────   ────────────────────────────────
P5_SYNTHETIC_MODE=1              P5_SYNTHETIC_MODE=0 (或未设置)
consumed_non_outcome_objects=[]  consumed_non_outcome_objects 从实际库存填充
                                 
↓                                ↓
跳过清单成员资格校验               执行清单成员资格校验
frozen_manifest_hash_set 未填充   frozen_manifest_hash_set 从生产清单构建
                                 
↓                                ↓
PC6 条件永远不会被触发             某些 staged object 不在冻结清单中
                                 → 触发 PC6_STAGED_OBJECT_NOT_IN_FROZEN_MANIFEST
                                 
↓                                ↓
计划创建成功 → PASS               计划不可满足 → 运行时失败或静默错误
```

核心问题在于：**测试的合成路径与生产代码路径存在结构性分叉**，而不仅仅是数据差异。合成模式不是"用不同数据测相同逻辑"，而是"走了一条完全不同的逻辑分支"。

### 应该捕获此问题的回归测试

```
场景：相同的输入，分别以 SYNTHETIC_MODE=1 和 SYNTHETIC_MODE=0 运行
      （使用一个完整的、合法的生产 inventory）
期望：两者在清单合规路径上的行为一致；

```

**3. 非空 consumed_non_outcome_objects 的清单覆盖测试**
```
场景：consumed_non_outcome_objects 包含真实对象，
      其中一个的哈希不出现在 frozen_manifest_hash_set 中
期望：PC6 被触发，即使 SYNTHETIC_MODE=1 也应如实反映
```

**4. 冻结清单哈希集合的构建完整性测试**
```
场景：在清单对象列表不完整时创建 source plan

```

### 根本原因评估

这类缺口通常由以下模式产生：

- **测试替身过度简化**：合成模式最初是为了解耦外部依赖而引入，但随着业务逻辑复杂度增加，模式分叉越来越深，而测试却没有相应补充覆盖新分叉的边界。
- **前提条件未作为一等公民测试**：PC6 这类"拒绝路径"（rejection path）往往只在实现时被手动验过，没有作为回归用例固化下来。
- **布尔标志掩盖了条件等价性**：`P5_SYNTHETIC_MODE` 这类标志在测试中往往被当作"简化开关"，但实际上它改变了被测代码的可达路径集合。

---

### 结论

合成 PASS **可以且确实掩盖了生产不可满足性**，因为 `P5_SYNTHETIC_MODE=1` 的代码路径跳过了 `frozen_manifest_hash_set` 的填充与校验，使得 PC6 在测试中成为死代码（unreachable）。

应补充的关键回归测试是：**在非合成模式下，使用包含清单外对象的真实 `consumed_non_outcome_objects`，断言 PC6 被触发**。同时应考虑对合成模式本身加入等价性约束，防止其绕过的逻辑范围随业务演化而无声扩大。
