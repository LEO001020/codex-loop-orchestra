## Duplicate Sol Hook Review — Findings

### 핵심 발견: 중복 Sol hook 등록

**두 개의 `hooks.json`** 파일이 동일한 `sol_tool_gate_router.py`를 `PreToolUse`에 등록하고 있습니다.

| 파일 | 매처 | 명령 |
|------|------|------|
| `E:\codex-LOOP\.codex\hooks.json` (외부/workspace 레벨) | `.*` (모든 툴) | `sol_tool_gate_router.py` |
| `E:\codex-LOOP\codex-loop-s-f2\.codex\hooks.json` (F2 프로젝트 레벨) | `^(shell\|shell_command\|bash\|...)` (prefix-specific) | `sol_tool_gate_router.py` |

### 중복의 성격 및 위험 분석

**1. 이중 실행 위험**
Desktop 런타임이 user-level hooks와 project-level hooks를 모두 적용하는 경우, 동일 tool call에 대해 `sol_tool_gate_router.py`가 **두 번** 실행됩니다. 현재 `cold_start` 모드에서는 router가 `v1_script`(`sol_tool_gate.py`)를 호출하고 결과를 pass-through하므로 이중 실행이 이중 deny가 되는 게 아니라 단순한 이중 실행이 됩니다. 실질적 enforcement 오류는 없지만 불필요한 overhead와 audit log 중복이 발생합니다.

**2. 매처 불일치**
외부 hooks.json의 매처는 `".*"` (모든 tool)인 반면, F2 프로젝트 hooks.json의 매처는 `^(shell|shell_command|bash|...)` (GATED_PREFIXES 전용)입니다. 이는 의도적 divergence이거나 업그레이드 시 정규화되지 않은 잔재입니다. 코드 내 `GATED_PREFIXES`와 정확히 align된 것은 F2 프로젝트 레벨 버전입니다.

**3. 역사적 맥락**
Archive 기록(`archives/pre-f2-desktop-complete-20260810T062825/outer-dot-codex.before/hooks.json`)을 보면, F2 설치 이전 outer hooks.json에는 **Sol gate가 없었습니다** (SubagentStart metering hook만 있었음). 외부 hooks.json의 Sol gate 등록은 F2 설치 과정에서 주입된 것으로, 그 후 F2 프로젝트 레벨에도 동일 등록이 존재하게 됩니다.

### 안전한 지연(Deferral) 경계 검토

**router의 deferral 경계** (`sol_tool_gate_router.py`)는 올바르게 설계되어 있습니다:
- `cold_start` 모드: v1 gate 호출 후 fail-open rollback (rc≠0 시 pass-through)
- `shadow` 모드: v1 enforce, v2 counterfactual 기록
- `layered` 모드: `layered_authorization()` 신선도 + policy hash 검증 실패 시 deny

`root_turn_governor.py`(v2 구현체, harness 레벨)의 deferral 경계는 다음과 같이 확인됩니다:
- **안전한 defer 조건**: 툴이 `GATED_TOOLS`에 해당하지 않으면 즉시 allow
- **fail-closed 경계**: 정책 파일 읽기 실패, ledger 읽기 실패, meter STALE/MISSING → 비-planning 상태에서 deny
- **planning lease 경계**: 빈 ledger의 "planning" 상태는 max_turns(6회)/max_new_tokens(30,000) 후 만료 → deny
- **planning 상태에서의 meter 실패**: fail-open (meter blind가 planning turn을 막으면 안 됨)

`live F2`와 `recovery-staging/prepatch-20260814-1318-candidate`는 `root_turn_governor.py`와 `sol_tool_gate_router.py` 모두 **SHA256 동일**, 현재 divergence 없음.

### 요약: 발견된 문제점

1. **중복 Sol hook 등록**: 외부(`E:\codex-LOOP\.codex\hooks.json`)와 F2 프로젝트(`codex-loop-s-f2\.codex\hooks.json`) 모두에 `sol_tool_gate_router.py`가 PreToolUse에 등록되어 있습니다. 이는 Desktop이 두 레이어를 동시에 적용할 때 동일 hook이 두 번 실행됩니다.

2. **매처 불일치**: 외부 hooks.json은 `".*"` (all tools)를 사용하고, F2 레벨은 GATED_PREFIXES에 정확히 align된 prefix-anchored 정규식을 사용합니다. 외부 레벨의 `".*"` 매처는 dispatch/spawn 툴에도 router를 트리거할 수 있으나, router 자체가 `GATED_PREFIXES`에 없는 툴을 내부에서 빠르게 통과시키므로 enforcement 오류는 아닙니다.

3. **safe deferral boundary는 견고함**: v2 governor(`root_turn_governor.py`)의 fail-closed/fail-open 분기 로직, planning lease 경계, attestation-required loop state 변경, hysteresis 등 핵심 deferral boundary 구현에는 문제 없습니다. live와 candidate 간 파일 동일성 확인 완료.

4. **수정 권고 (편집 없이 보고)**: 외부 `E:\codex-LOOP\.codex\hooks.json`의 PreToolUse Sol gate 항목을 제거하여 F2 프로젝트 레벨 hooks.json을 단일 권한으로 유지해야 합니다. 혹은 F2 설치 절차가 의도적으로 outer hooks에 fallback을 주입한 것이라면, 두 등록의 matcher를 동일하게 정규화해야 합니다.
