## 3. 推断

1. **真正的“启动项”层在 Honor 应用启动管理 / powergenius，不在 `BOOT_COMPLETED` 清单。** Stage5 已实测 `cmd powergenius` 无写接口。shell 能做的跨 reboot 保活只有 `deviceidle whitelist +pkg`。流畅度若要减开机后台，用户 UI 关“允许后台运行 / 自动管理”才碰得到 PG 未保护↔保护。
2. **B 站从 Protected → Unprotected、doze user 行消失，更像 Honor 策略漂移或用户/系统名单改写，不是 Reduced 重放。** 重放只会 `RUN_ANY=ignore`，不会删 `user,com.bilibili.app.in`；`keep_alive` 还要求 `ensure_present`。对流畅度：漂移会 **减轻** B 站开机保活成本，同时违反用户保活目标。本包不把“加回白名单”标成流畅度杠杆。
3. **GKD 是开机后唯一启用的无障碍 + 仍在跑 overlay。** STATUS_FOR_WEB_GPT 已标 KEEP。它不是 Honor 启动管理项，但是跨 reboot 的输入/合成层成本。
4. **微信/QQ/支付宝 CoreService 是硬保留通讯栈，不是可清启动项。** 它们长期在 user whitelist。
5. **`hnstartupguide` 出现在 `mExemptPkgList` 是云名单滞后，不是自启残留进程。**
6. **user128 闲鱼 + GMS `BOOT_COMPLETED` 是第二用户开机税。** 流畅度若在分屏/平行空间场景卡顿，先测关分屏，不要禁 GMS。

## 7. 如何测 jank（与启动项相关）

目标：区分「开机 2–5 分钟的自启税」和「亮屏滑动卡顿」。

1. **冷启动窗口（reboot 后不要先开重应用）**
   - `uptime` / `dumpsys gfxinfo com.hihonor.android.launcher reset` 后 Home→横滑→Recents→Home→下拉（与 Stage3 PRE/POST 同一手势）。
   - 记录 launcher / SystemUI：frames、jank%、p50/p90/p99、deadline missed。Stage3 基线曾是 launcher jank 3.15%→2.54%、SystemUI 9.04%→3.03%（不能把因果全归禁包）。
2. **开机 3 分钟进程税**
   - `dumpsys activity services` 是否仍有 GKD SelectToSpeak、微信 CoreService、GMS LifecycleService、Dolby BOOT_COMPLETED。
   - `dumpsys cpuinfo` / `top -b -n 1` 看 `li.songe.gkd`、`gms.persistent`、`pushagent`、`hiboard`。
3. **保活成本对照（网易云 / B站）**
   - `dumpsys deviceidle whitelist` 是否含 `user,com.netease.cloudmusic` / `user,com.bilibili.app.in`。
   - `dumpsys usagestats` bucket：网易云期望 5；B 站 live 曾到 10。
   - `dumpsys powergenius -a` 的 Protected vs Unprotected（只读）。
   - 息屏 10 分钟再亮，看媒体是否断、再跑同一 gfx 手势。
4. **GKD 开关 A/B（仅用户同意）**
   - 关无障碍前后各跑一次 gfxinfo `li.songe.gkd` 与 launcher；对比 overlay `CREATE_ACCESSIBILITY_OVERLAY` 是否仍 running。
5. **不要用** `am startservice` 测 hndockbar（会留僵尸 ServiceRecord）；不要 `adb input swipe` 当侧栏/热区验证。

验收：若只关“已冻的启动向导”而 jank 不变，说明开机成本已不在 UAD 包上，而在 GKD / 通讯保活 / Honor PG 未保护应用 / 双用户 GMS。
