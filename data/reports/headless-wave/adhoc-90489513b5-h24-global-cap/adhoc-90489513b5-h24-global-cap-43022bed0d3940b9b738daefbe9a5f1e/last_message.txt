### 2. Desktop 50-Cap Behavior

**Stated rule (AGENTS.md global section):**
> "Never exceed 50 active spawned subagents in one Desktop root session or any lower runtime limit; the primary agent is excluded from that count."

**Key nuance:** The primary/Sol agent is excluded, so up to 50 *child* agents may be active simultaneously in a single Desktop root session.

**Transport preference (AGENTS.md §6):**
> "Wide execution normally uses WSL/headless `codex exec` workers so Desktop is a light control and observation plane."
> "Prefer keeping only the first 8 children Desktop-native and placing the rest of a wide wave on the existing headless `codex exec` plane."

**Finding:** Desktop-native birth is *preferred* only for the first 8 of a wide wave. This is a transport preference, not an effective-concurrency cap. The rule explicitly states: *"Eight is a transport preference, never an effective-concurrency cap."* A native birth may only be blocked after the same task has been durably submitted headless and stably observed as `running`.

### 3. Headless Borrowing — Safe Registration Requirements

The AGENTS.md imposes strict requirements before headless workers count toward filling the 80-target:

**Required registration path:**
> "Ad-hoc headless waves use `harness/headless_wave.py` so each birth is owned by `lifecycle_supervisor.py`, appears in `exec_roster.json`, and is visible on 8765."

**What does NOT satisfy refill debt (explicitly excluded):**
- A raw unregistered `codex exec` process
- A process in `starting` state
- Spawn intent alone
- Deny messages
- Stale/lost rows in the roster
- A bare `Popen` success

**What DOES count as effective concurrency:**
> "Only the matching generation stably observed as `running` counts as effective; `starting`, spawn intent, deny messages, stale/lost rows, and Popen success do not reduce the 20/80 deficit."

**Generation-matching requirement:** The harness must produce a matching exec-roster generation that is *stably observed as `running`*. A one-shot ad-hoc manifest launched outside `parent_manifest_importer.py` is observable but does not constitute a sustained-concurrency backlog.

**For parent-dialogue refill above 20:**
> "Compile 21–80 real, bounded read-only packets into `codex-loop-parent-refill/v1` and admit them once through `harness/parent_manifest_importer.py` with `target_active=20`. The importer wakes the existing refill consumer; do not launch the same packets separately through a second wave."

### 4. Birth Rate and Health-Check Constraints

- At most **8 agents** may be in the initializing handshake simultaneously
- Every **8th birth** triggers a lightweight OpenCodex health check
