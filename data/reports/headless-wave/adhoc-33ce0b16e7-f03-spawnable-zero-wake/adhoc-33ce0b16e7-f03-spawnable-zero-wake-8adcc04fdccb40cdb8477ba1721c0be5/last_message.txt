## 审计结论：容量释放再唤醒永久欠债路径

### 系统调用链概览

```
[Desktop 子代理结束]
    → SubagentStop hook → ?  ← 关键断点1
    → Stop hook → reconcile_subagent_metering.ps1 (仅计量) ← 关键断点2
                            ↓
      subagent_lifecycle.py::handle() 在 SubagentStop/Stop 时
      调用 schedule_refill_actuator()  ← 但此路径在hooks.json中未接线
```

### 发现的缺陷路径

#### **P0：SubagentStop 完全未接线到 lifecycle hook**

`hooks.json` 中：

```json
"SubagentStop": []
```

`subagent_lifecycle.py::handle()` 里明确处理了 `SubagentStop`，并且在 `SubagentStop` 触发时会调用 `schedule_refill_actuator()`，但 **hooks.json 的 `SubagentStop` 数组为空**。也就是说，Desktop-native 子代理结束时，lifecycle hook 脚本根本不会被调用。

`Stop` 上挂的是 `reconcile_subagent_metering.ps1`，而不是 `subagent_lifecycle.py`，所以计量会刷新，但**再唤醒 actuator 的调用不会发生**。

`handle()` 函数中触发 `schedule_refill_actuator` 的唯一路径：

```python
def handle(event, payload, sessions=None):
    ...
    elif event == "SubagentStop": subagent_stop(roster, payload)  # 调用 schedule_refill_actuator
    elif event == "Stop":         parent_stop(roster, payload)     # 也调用 schedule_refill_actuator
    ...
    if event in ("SessionStart", "SubagentStop", "Stop"):
        refresh_meter()
```

但由于 hooks.json 未注册 `subagent_lifecycle.py` 到 `SubagentStop` 和 `Stop`，这两条路径在生产上均不生效。

---

#### **P1-A：`run_once` 的 idle 提前返回不触发任何后续 wake**

```python
def run_once(root, *, dry_run=False, observe_timeout=5.0):
    with file_lock(...consumer.lock):
        controller.queue_sync_ledger()
        before = controller.recompute()
        manifest = build_manifest(paths, before)
        if manifest is None:
            return 0, {"status": "idle", "state": before, "manifest": None}
        # ... headless_wave.run() ...
        after = controller.recompute()
        retry_wake = schedule_followup_if_debt(root, after, ...)
        return rc, {..., "retry_wake": retry_wake}
```

当 `build_manifest()` 返回 `None`（即 `select_tasks()` 为空列表），原因是：

- **全局 capacity = 0**（running ≥ target_total），即 `reason = "at_capacity"`

此时 `before["deficit"]["total"] > 0` 但 `select_tasks` 产出空（因为 spawnable=0），manifest=None，**`schedule_followup_if_debt` 不被调用**，actuator 静默退出。

如果此时一个子代理随后结束（释放容量），但：
1. `SubagentStop` 未接线 → `schedule_refill_actuator` 不被触发
2. `Stop` 接的是 metering ps1 → 同样不触发 actuator

系统进入**永久欠债静默态**：deficit>0、capacity 随后释放、但无任何机制再唤醒 actuator。

---

#### **P1-B：`schedule_followup_if_debt` 检查的是 `after.deficit.total` 而非 `before.deficit.total`**

```python
retry_wake = schedule_followup_if_debt(
    root, after, failed=bool(rc),
    source=("refill_debt_backoff" if rc else "refill_residual_debt"))
```

```python
def schedule_followup_if_debt(root, state, *, failed, source):
    if int((state.get("deficit") or {}).get("total", 0) or 0) <= 0:
        return None
    ...
```

`after` 是在 `headless_wave.run()` 之后重新计算的状态。若这次 dispatch 消耗完所有可分配的 deficit，`after["deficit"]["total"] == 0`，则 **follow-up wake 不被安排**。即使 20 个子代理随后在接下来 30 秒内全部结束释放容量，也不会有后续 actuator 运行。只能靠外部边沿触发（如 SessionStart 或人工调用）。

---

#### **P1-C：exec_roster 冷启动重建后无 wake**

`cold_reconcile_exec()` 在 `SessionStart` 时将僵死 exec 任务标记为 `lost`，并调用 `recompute_refill()`（controller 只 observe+decide），然后调用 `schedule_refill_actuator()`。但：

- 若会话进程崩溃重启时 Codex Desktop 未触发 `SessionStart`（例如在 Windows 上通过进程替换而非完整新会话），则冷启动重建不会发生
- `exec_roster` 中条目状态仍为 `running`（supervisor_pid 已死但 TTL=1800s 尚未超时），controller 将这些僵死行计入 running 总数，抑制 deficit 计算

### 最小复现场景

**P0（SubagentStop hook 丢失）：**

1. LOOP 运行中有 deficit>0，capacity=0（20 个 native 子代理全部在跑）
2. 一个子代理结束 → Desktop 触发 `SubagentStop`
3. `hooks.json["SubagentStop"] == []` → 没有任何 Python hook 被调用
4. native_roster 中该 agent 仍标记 running（TTL 未过，observer 也未更新）
5. running count 未减少 → capacity 仍为 0 → deficit 继续 = N
6. **无任何 wake 被安排**，波浪永久停滞

**P1-A（idle 提前返回后容量释放）：**

1. t=0: deficit=5，capacity=0，actuator 运行，`build_manifest()` 返回 None，返回 `idle`
2. t=1: 5 个子代理结束，capacity=5
3. 由于 hooks.json 未接线 SubagentStop，actuator 不被调用
4. `idle` 返回路径没有安排任何 delayed wake
5. **deficit=5 永久可见，spawnable=5 但无人消费**

### 应有的不变量

以下不变量当前**未被满足**：

**INV-1（终态必须触发 actuator）：** 每一个 Desktop-native 子代理终止（`SubagentStop`）或 headless 任务终止（exec_roster `state=lost/completed`），必须有且只有一次对 `schedule_run(root, source=...)` 的调用，且该调用在 `subagent_lifecycle.py::subagent_stop()` 或等效路径中完成。当前 INV-1 被违反：hooks.json 中 SubagentStop 为空数组。

**INV-2（idle 返回路径不可丢失债务）：** 当 `run_once()` 因 `build_manifest() == None` 而以 `status=idle` 返回时，若 `before["refill_required"] == True`（即存在 pending 但 capacity=0），必须安排一个 delayed wake，等待 capacity 有可能释放后重新评估。当前没有此逻辑。

**INV-3（capacity 释放事件必须关联到 actuator 调度）：** roster 中任一 `running → terminal` 转换都应使 running_total 减少并触发 recompute。目前 native roster 的 TTL 上限为 1800s，意味着僵死行会抑制 capacity 识别最多 30 分钟。

**INV-4（follow-up wake 基于 before 债务，而非 after 债务）：** `schedule_followup_if_debt()` 应检查 `before["deficit"]["total"]`，即本次 dispatch 之前是否有债务存在，而非 dispatch 之后是否清零。仅当 before 有债、after 清零时，才意味着本次完全满足，此时不需要 follow-up 是正确的。但若 after.deficit=0 是因为 spawn 行为只占用了 initializing 而非 running（births 不减 deficit），则可能误判为无债。

---

### 缺陷定级汇总

| ID | 位置 | 描述 | 级别 |
|---|---|---|---|
| BUG-1 | `hooks.json["SubagentStop"] == []` | Desktop native 子代理终止不触发任何 lifecycle hook，wake 永远丢失 | **P0** |
| BUG-2 | `run_once()` idle early-return | capacity=0 时 idle 退出，没有安排等容量释放后的 delayed wake | **P1** |
| BUG-3 | `Stop` hook 接的是 metering 脚本而非 lifecycle.py | parent_stop → schedule_refill_actuator 路径对 Desktop 根 session 失效 | **P1** |
| BUG-4 | native roster TTL=1800s | 僵死行可持续 30 分钟错误抑制 capacity，使 INV-3 在 exec 崩溃时失效 | **P1** |

---

**结论：存在 P0 级永久欠债路径。** 核心缺口是 `hooks.json["SubagentStop"]` 为空数组，导致 Desktop-native 子代理终止事件完全不触发 `subagent_lifecycle.py`，而该脚本是 `schedule_refill_actuator()` 的唯一 Desktop 触发路径。当容量满载后有 N 个子代理结束，capacity 释放但无任何 wake 被安排，系统停留在 deficit>0、spawnable=0 的永久静默态。`run_once()` 的 idle 提前返回（BUG-2）与此形成双重故障：即使主动调用 actuator 也会因 capacity=0 被 idle 返回，同样不留任何后续 wake。
