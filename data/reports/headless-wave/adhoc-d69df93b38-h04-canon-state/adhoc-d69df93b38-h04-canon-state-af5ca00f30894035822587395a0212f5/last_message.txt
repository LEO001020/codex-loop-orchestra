## 6. 如何测 jank（不碰 CANON）

侧栏成功判据（**验证不是写入**；不要把空闲未展开当失败）：必须同时 `show dock`（或等价 bind）**且** `HnDockBarFloatWindow` **且** 右侧展开 `dockBar=-1`。只 bind 不算修好失败。空闲后 `dockBar` 回到 0、无 FloatWindow、hndockbar 可再被 iAware 停掉 — **这是收起，不是回退。**

流畅度测量协议（只读；ADB 钉 5038；**禁止**为测而 crash/force-stop/改 settings）：

1. **钉场景，分表记录。** 至少三档：桌面全屏轻滑、普通全屏应用内滑、u128 闲鱼左右分屏。禁止用分屏闲鱼宣称桌面流畅度。
2. **短窗、重置计数。** 对 launcher / SystemUI / 当前前台 `dumpsys gfxinfo <pkg>` reset 后 10–20s。Stage2 已证累计 jank% 随分母变大而“变好”，不能当收益。
3. **记负载协变量，不把它们当该改的 CANON 字段：** load、前台 LRU、网易云是否仍在 whitelist、Reduced 是否仍 29、`navigation_mode` 是否仍 106、`is_ota_finished` 是否仍 1。CANON 字段被改 = 实验污染，作废。
4. **热区/侧栏只作回归探针。** 测前只读确认 `GestureNavDock` 仍在、FloatTasks 仍 disable-user。不要为“减少 overlay”去动 GKD 或 FloatTasks。
5. **Perfetto / systrace 若用：** 输出放到 `reports/` 或 `work/fluency_plan/`；不要 reboot 当测量步骤（门闩缺在 freeze 里，reboot 有掉 0 的开放风险）。
6. **负向对照：** jank“改善”若伴随 `navigation_mode≠106`、`tooltip=0`、`is_ota_finished=0`、B 站进入 ignore、网易云出白名单，判为 **中毒不是优化**。
