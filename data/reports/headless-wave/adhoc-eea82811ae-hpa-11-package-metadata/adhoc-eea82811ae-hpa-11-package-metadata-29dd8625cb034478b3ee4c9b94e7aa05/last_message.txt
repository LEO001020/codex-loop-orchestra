### 三、身份字段分类

#### 3A. 兼容性所需、**不应**改为 K3 Harness 的名称

这些字段存在于编译产物和内部 import 路径中，改动会破坏构建：

- **workspace 包的 `name` 字段**（`@earendil-works/pi-*`）——源包名嵌入所有已编译的 `import` 解析路径；`pack-prime-agent-release.mjs` 在发布时统一改写，源码层无需变动。
- **`packages/coding-agent` 的内部 `bin.pi`**——`piConfig` 机制在发布打包时将它改写为 `prime-agent`。
- **内部进程间通信标记**（`PRIME_AGENT_INTERNAL_*` 环境变量、`\0prime-agent-runtime-command` marker）——这些是进程边界协议，改动需要版本门控。
- **Python 内核变量前缀** `_prime_agent_*`——IPython 沙箱内部命名空间占位符，不对用户可见。
- **`PRIME_AGENT_META_NAMESPACE = "ai.primeintellect.prime-agent"`**——ACP 协议命名空间，已进入线上协议，改动需要协议版本或 capability 门控。

#### 3B. 应改为 K3 Harness 的**用户可见**身份（或需明确标注）

| 字段/位置 | 当前值 | 问题 |
|---|---|---|
| `packages/coding-agent/README.md` 标题 | `Prime Agent CLI` | 已有警示框说明，但 H1 标题仍是 Prime 品牌 |
| `packages/ai/README.md` 标题 | `Prime Agent AI` | 同上，用户可见 |
| `packages/agent/README.md` 标题 | `Prime Agent Core` | 同上 |

### 四、关键结论

1. **内部 npm 包名**（`@earendil-works/pi-*`）和**内部 bin 入口**（`pi`）是兼容性保留项，不需要也不应该改为 K3 Harness 名。`pack-prime-agent-release.mjs` 已正确处理发布时的改写。

2. **用户可见的主要身份锚点**是：
   - `piConfig.name = "prime-agent"` → 运行时 `APP_NAME`，决定 TUI 提示符和命令帮助文本。
   - `piConfig.configDir = ".prime/agent"` → 用户数据目录。
   - `prime-agent-runtime` Python 包名 → 内核 venv 中安装的包名，用户在错误消息中看到。

3. **所有包的 `repository.url` 均指向 `PrimeIntellect-ai/prime-agent`**，若 K3 Harness 希望独立可见性，需更新（或保留并在 README 中明确说明是 fork）。

4. **`CONFIG_DIR_NAME` 的硬编码兜底值 `".prime/agent"`**：当前 `packages/coding-agent/package.json` 中的 `piConfig.configDir` 已显式设置为 `".prime/agent"`，所以兜底值从未触发——但两者同为 Prime 品牌路径，若 K3 Harness 要求独立的用户数据目录，需同时修改 `piConfig.configDir` 和兜底值。
