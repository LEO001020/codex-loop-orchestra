针对 Codex 插件的前端字段支持，其核心规范源自官方的 `plugin-json-spec.md`。

根据对当前环境中 `plugin-creator` 相关配置文件的直接读取，`plugin.json` 的前端字段支持情况如下：

### 核心支持字段
在官方 schema 定义中，`plugin.json` 支持以下结构化字段：

*   **基础元数据**：
    *   `name`：插件唯一标识（kebab-case，必需）。
    *   `version`：语义版本号。
    *   `description`：用途总结。
    *   `author`：发布者信息（包含 `name`, `email`, `url`）。
    *   `homepage`, `repository`, `license`, `keywords`：插件文档与发布属性。

*   **路径与配置引导**：
    *   `skills`：技能目录相对引用。
    *   `hooks`：Hook 配置文件路径。
    *   `mcpServers`：MCP 服务器配置文件路径。
    *   `apps`：插件应用清单路径。

*   **界面元数据 (`interface` 块)**：
    *   `displayName`：用户界面标题。
    *   `shortDescription` / `longDescription`：副标题与详情页描述。
    *   `developerName`：人类可读的发布者名称。
    *   `category`：插件分类。
    *   `capabilities`：能力列表。
    *   `websiteURL` / `privacyPolicyURL` / `termsOfServiceURL`：法律与网站信息。
    *   `defaultPrompt`：作曲界面或上下文中的 starter prompts（上限 3 个，每条限 128 字符）。
    *   `brandColor`：品牌主题色。
    *   `composerIcon` / `logo`：资产引用路径（推荐存放在 `./assets/`）。
    *   `screenshots`：界面截图列表。

### 现场证据核验
在本项目 `E:\Program Files\ZCode\resources\glm\packages\zcode-guide-plugin\.zcode-plugin\plugin.json` 实地检查中，确认了最小化配置实践：
该插件仅包含了 `name`, `version`, `description`, `author`, `license`, `skills` 等基础信息，未在 `plugin.json` 中配置 `interface` 块，表明 Codex 遵循了“基础字段必要，界面字段可选”的插件发现原则。

所有官方定义的字段均由 `plugin-creator` 工具链强制校验，本地实现的清单（如 `zcode-guide`）需符合该 schema 并通过 `marketplace.json` 生成注册。
