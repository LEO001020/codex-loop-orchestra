## 二、Canonical manifest/package SHA256 方法（设计）

**目标属性**：跨平台确定（与 mtime、目录顺序、缩进、CRLF 无关）；排除字段晚绑定/签名后哈希不变（先签草稿哈希、后填值）；草稿状态门禁；具体值出现时 fail-closed。

**1. 范围**
- 纳入：MANIFEST.json 列出的 9 个工件。
- 排除：MANIFEST.json 自身（避免自指）与 verification.log（可再生输出）。
- 包哈希 = 对 canonical manifest 的 SHA256，即哈希根是 manifest 本身，不是任何文件字节。

**2. 逐工件 canonical 化**
- JSON 工件：解析 → 删除排除字段（见下）→ 递归按键名字典序排序 → 紧凑序列化（与 RFC 8785 JCS 等价；本数据集无浮点、无代理对/U+2028 等边界字符，直接用 sorted-key compact JSON 即可）→ UTF-8 无 BOM、无尾随换行。
- 非 JSON（.md/.py）：UTF-8 无 BOM、CRLF→LF，其余字节原样。不剥离空白（代码/文档的空白是语义的一部分）。

**3. 排除字段 schema（DRAFT_SCHEMA_V1）**
- 签名/执行值：`owner_signature`、`signature`、`signable_bytes_sha256`、`delegation_id`、`registered_at`、`applied_at`、`daemon_ledger_sequence`；
- owner 晚绑定值：`owner_identity`、`owner_session_id`、`issued_at_verified_external_time`、`expires_at`、`parent_delegation_nonce`、`wave1_wall_time_expiry`、`wall_time_expiry_seconds`；
- 密钥材料兜底：`private_key`、`secret_key`、`private_key_pem`、`seed_phrase`、`mnemonic`、`passphrase`（本包均不存在）。
- 规则：排除字段值为 `null` 或 `<PLACEHOLDER>` 时删除；占位符属于 schema 标记、不是晚绑定值，保留含义由字段名表达；**出现具体值必须整体失败**，不能静默丢弃（防"藏值"）。
- 例外：键名为 `bindings`、且值为全字符串的描述性词汇表原样保留（机器清单中 `bindings.owner_signature = "owner only; agent and daemon cannot create it"` 是文字说明而非签名值，与现有 verifier 的 `.bindings.` 例外一致；建议两处统一成"全字符串 glossary"规则，比路径前缀更严格）。

**4. Canonical manifest 结构**
```json
{
  "canonical_id": "P5_OWNER_CEREMONY_PACKAGE_MANIFEST_V1",
  "manifest_schema_version": "CANONICAL_V1",
  "ceremony": "ONE_HUMAN_CEREMONY",
  "status": "DRAFT_UNSIGNED_UNEXECUTED",
  "hash_policy": {
    "encoding": "UTF-8_NO_BOM", "line_endings": "LF",
    "json": "RFC8785_JCS_EQUIVALENT_SORTED_KEYS",
    "exclusions": {"key_material": true, "signatures": true, "owner_late_bound_values": true},
    "excluded_fields_schema": "DRAFT_SCHEMA_V1"
  },
  "files": [{"relative_path": "...", "canonical_sha256": "...", "bytes": 123}]
}
```
`files` 按 `relative_path` 字典序排序。建议下一版 manifest 同时保留现有 raw `sha256` 列作篡改检测（任何字节改动都会暴露），`canonical_sha256` 作语义绑定。

**5. 包哈希与签名绑定**
`package_sha256 = SHA256(上述 canonical manifest 的 UTF-8 字节)`。签名阶段签名的是这个包哈希（连同 canonical_id、status），而不是可变文件；此后晚绑定值/签名字段被填入时哈希不变，草稿承诺依然可验。任何签名/执行事件发生后草稿哈希失效，必须换 canonical_id 与状态，不得复用。

**6. 状态门禁**：哈希仅在 `status == "DRAFT_UNSIGNED_UNEXECUTED"` 时有效（manifest 与机器清单双重声明）；verifier 应同时校验排除字段具体值缺失与状态前缀家族，两个条件缺一即 FAIL。
