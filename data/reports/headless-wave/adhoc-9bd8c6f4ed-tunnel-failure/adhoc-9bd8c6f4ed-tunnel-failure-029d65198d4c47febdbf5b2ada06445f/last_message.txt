## 隧道失效模式审计报告

**文件：** `p5_filebrowser_tunnel_supervisor.ps1`  
**状态目录：** `p5-filebrowser-tunnel/`

---

### 1. 端口配置

| 项 | 值 |
|---|---|
| 本地监听地址 | `127.0.0.1:8766` |
| 远端转发目标 | `127.0.0.1:8080`（远端机器本地） |
| SSH 转发规范 | `-L 127.0.0.1:8766:127.0.0.1:8080` |
| SSH 仅 IPv4 | `-4` 标志强制 |

`LocalPort` 默认 `8766`，可通过脚本参数 `-LocalPort` 覆盖。

---

### 2. 健康检查机制

脚本用 `Test-Endpoint` 函数检查健康性：向 `http://127.0.0.1:8766/` 发送 HTTP GET，超时 5 秒，要求返回 HTTP 200。仅 HTTP 状态码等于 200 才视为健康，其他一律视为失败。

轮询间隔由 `PollSeconds`（默认 3 秒）控制。每次循环都先用 `Get-OwnedTunnel` + `Test-Endpoint` 双重判断：
- `ssh.exe` 进程存在 **且** HTTP 200 → 状态 `READY`，重置退避
- `ssh.exe` 进程存在但 HTTP 失败 → 杀掉旧进程，重新拉起

---

### 3. 自动重连逻辑

重连流程：

1. 检查端口 `8766` 是否被非自有进程占用 → 若占用则进入 `DATA_MOUNT_BLOCKED`，跳过本轮，不重连
2. 否则用完整参数启动新 `ssh.exe`（`-WindowStyle Hidden`）
3. 最多等待 **15 秒**（250ms 轮询）让隧道就绪
4. 就绪则写 `READY`，失败则杀进程，写 `RETRYING`，进入退避
5. 退避：初始 **1 秒**，每次失败翻倍，上限 **30 秒**（`$backoff = [Math]::Min($backoff * 2, 30)`）

优雅停止：检测到 `STOP` 文件即退出循环，杀掉自有隧道，写 `STOPPED`。

`auto_recovery_canary.json` 记录了一次实际恢复：旧隧道 PID 47756 死亡约 31 秒后（18:17:18 → 18:17:49），新隧道 PID 26380 建立并通过 HTTP 200，`TUNNEL_AUTO_RECOVERY=PASS`。

---

### 4. 失败语义（status 枚举）

| Status | 含义 |
|---|---|
| `READY` | SSH 进程存在且 HTTP 200，一切正常 |
| `RETRYING` | 本轮重连未能在 15s 内建立健康隧道；进入指数退避后重试 |
| `DATA_MOUNT_BLOCKED` | 端口 8766 被非自有进程占用，supervisor 不强行抢占，等待解除 |
| `FAIL_CLOSED` | 启动前置检查失败（见下文凭据依赖），脚本 `throw` 退出，不进入循环 |
| `STOPPED` | `STOP` 文件触发优雅停机 |

---

### 5. 凭据与文件依赖

启动时逐一用 `Test-Path -PathType Leaf` 检查三个必要文件，缺任何一个即写 `FAIL_CLOSED` 并 `throw`：

| 依赖项 | 路径 | 说明 |
|---|---|---|
| SSH 可执行文件 | `%WINDIR%\System32\OpenSSH\ssh.exe` | 系统内置 OpenSSH |
| 私钥 | `C:\Users\hzq00\Downloads\pi-agent\VPS\**\k3_p4_fable_ed25519_PRIVATE_KEY.txt`（递归搜索首个匹配） | Ed25519 私钥；路径含用户名 `hzq00`，跨用户不可移植 |

SSH 参数中强制排除所有其他认证方式（`BatchMode=yes`、`IdentitiesOnly=yes`、`IdentityAgent=none`、`PasswordAuthentication=no`、`KbdInteractiveAuthentication=no`），仅允许 `publickey`。`StrictHostKeyChecking=yes` 且 `GlobalKnownHostsFile=NUL`，唯一有效的 known_hosts 就是上表中的固定路径。

### 关键风险总结

- **`DATA_MOUNT_BLOCKED` 无解除机制**：端口被占期间 supervisor 仅轮询等待，不告警，不尝试重新绑定，持续阻塞。
- **`FAIL_CLOSED` 不可恢复**：三个依赖文件任意一个缺失，脚本直接 `throw` 退出，不进入重试循环。私钥路径是递归搜索取第一个匹配，若 Downloads 目录有多个同名文件，实际加载哪一个存在不确定性。
- **连接存活参数偏激进**：`ServerAliveInterval=15` + `ServerAliveCountMax=2` = 约 30 秒无响应即断线，这触发了日志中观察到的那次自动重连。
