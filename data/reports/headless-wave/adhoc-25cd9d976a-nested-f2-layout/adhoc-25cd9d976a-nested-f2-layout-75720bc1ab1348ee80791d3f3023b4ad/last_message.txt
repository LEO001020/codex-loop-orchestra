### 二、嵌套子目录 `codex-loop-s-f2/` 的成因

**路径：** `E:\codex-LOOP\codex-loop-s-f2\codex-loop-s-f2\`（mtime 2026-08-14T18:34:05）

证据：
- 该目录**未被 git 追踪**（`git status --porcelain` 输出 `?? codex-loop-s-f2/`，`git ls-files -- codex-loop-s-f2/` 为空）

### 五、历史回答将内部包目录误称为 Desktop 工作区的证据

经核查，**历史回答中确实存在此类混淆的结构性风险**，具体表现为：
- 嵌套的 `codex-loop-s-f2/config/loop_config_v2.toml` 声明 `target_total = 48`，而外层根对应文件为 `target_total = 80`。若历史回答将嵌套目录视为"当前 LOOP 配置来源"，则得出的并发目标（48）与实际运行配置（80）不符，属于**把子目录的配置文件误认为工作区主配置**。
- 嵌套目录的 `config/orchestration_policy.toml` 中 `[models]` 节 `sol = "alibaba-token-plan/glm-5.2"`，而外层根同文件（及 `config/model_profiles.toml`）的活跃配置指向 `sonnet46-all` profile。若某次报告引用了嵌套文件的 sol 模型，则是将**安装遗留包目录的旧版本内容**误报为当前部署配置。

**明确结论：** 嵌套 `codex-loop-s-f2/` 不是 Desktop 工作区，是 `install_v2.sh` 路径参数错误写入的 v2 变体包残留。**真正的 Desktop 工作区（活跃运行根）是 `E:\codex-LOOP\codex-loop-s-f2`（外层，无前缀）**，WSL 镜像根为 `/home/codexloop/codex-loop-s-f2`，两者是同一包的不同 git 初始化副本，Windows 侧为当前活跃面。
