### 一、什么是"云重授予"（cloud regrant）

本包中，"云重授予"特指 GCP 托管虚机上以下两条路径可以绕过本地 `sudoers` 清理、从云控制层恢复 agent（`k3`）的 root 权限：

1. **`google-guest-agent` systemd 服务**：GCE Guest Agent 会定期从 GCP Instance Metadata 拉取 OS Login / IAM 策略并重写 `/etc/sudoers.d/google_sudoers`，如果 k3 在 IAM 上有 `roles/iam.serviceAccountUser` 或 `roles/oslogin.admin`，则每次 guest-agent 运行都会重新写入 `sudo` 特权。
2. **`/etc/sudoers.d/google_sudoers` 文件存在**：即使服务未运行，该文件存在表明曾由 guest-agent 写入，下次 guest-agent 启动时会刷新。

---

### 二、探测动作（只读 / Codex 可验证）

在 `01_PRE_CUTOVER_READONLY_PREFLIGHT.sh` 中，Codex 可执行以下**只读探测**：

```bash
for unit in google-guest-agent google-osconfig-agent; do
  systemctl is-enabled "$unit" >/dev/null 2>&1 &&
    open "cloud regrant agent enabled: $unit" || true
done
```

**作用**：标记开放项（`[OPEN]`），输出 `PREFLIGHT_OPEN_COUNT=N`。这是纯只读操作，不修改任何系统状态。

### 三、中和动作（必须由 Human / Provider 执行）

在 `03_AGENT_PRIVILEGE_CUTOVER.sh` 中，云重授予的中和**不由脚本自动执行**，而是要求操作者在运行脚本之前完成，脚本仅做"事后门控断言"：

```bash
if systemctl is-enabled google-guest-agent >/dev/null 2>&1 ||
   [ -e /etc/sudoers.d/google_sudoers ]; then
  [ "${P5_CLOUD_REGRANT_NEUTRALIZED:-NO}" = YES ] ||
    die "cloud IAM/OS Login/metadata regrant not independently neutralized"
fi
```

**含义**：
- 触发条件：`google-guest-agent` 已 enabled，或 `/etc/sudoers.d/google_sudoers` 存在。
- 如果触发，脚本要求环境变量 `P5_CLOUD_REGRANT_NEUTRALIZED=YES` 已被设置，否则 `die`（fail-closed 失败退出）。
- 该变量必须由独立的 human/provider 在脚本之外设置，代表其已完成以下一项或多项实际的云端操作。

**Human / Provider 必须独立完成的实际中和动作**（脚本描述为"cloud IAM/OS Login/metadata regrant"）：

| 中和类型 | 必须由 Human/Provider 在 GCP 控制台或 `gcloud` CLI 完成的操作 |
|---|---|
| IAM 层 | 从 GCP IAM 绑定中移除 k3 service account 的 `roles/oslogin.admin`、`roles/iam.serviceAccountUser` 及任何可写元数据的角色 |
| OS Login 层 | 在项目或实例元数据中禁用 OS Login（`enable-oslogin=false`），或从 k3 账号注销 OS Login 授权 |
| Metadata server 层 | 确认 k3 无法再通过 instance metadata endpoint（`169.254.169.254`）获取可授权凭证 |
| Guest Agent 层 | 禁用或停止 `google-guest-agent`；或删除 `/etc/sudoers.d/google_sudoers` |

完成上述操作后，操作者显式设置 `export P5_CLOUD_REGRANT_NEUTRALIZED=YES`，再调用脚本，方可通过此门控。

### 四、机械验证（Codex 可做、不修改云资源）

门控通过后，`03` 脚本继续执行**本地可验证**的断言，确认云重授予路径已清除：

1. `visudo -c`：验证清理后 sudoers 语法合法，无残留 k3 条目。
2. 对所有 `ROOT_EQUIVALENT_GROUPS`（含 `google-sudoers`）逐一检查 k3 是否仍在其中。
