## 形式化分析：空 backlog 时 deficit=0 的语义正确性

### 定义

设系统状态为一个五元组：

```
S = (target, running, pending, queue_empty, deficit)
```

其中：
- `target` = 期望的持续并发数（本例 = 20）
- `running` = 当前活跃 agent 数
- `pending` = 已知可调度的有效工作包数（有具体目标、有界、非 filler）
- `queue_empty` = 布尔值，表示 backlog 是否耗尽
- `deficit` = 应当补充的 agent 数

---

### 命题 1：target=20, running<20, pending=0, queue_empty=true → deficit=0 **在语义上正确**

**论证：**

`deficit` 的语义是"为满足并发目标而需要立即提交的新工作包数量"。

关键约束来自 AGENTS.md §6：

> "Never synthesize filler packets to satisfy a number. If the admitted parent backlog is exhausted, 8765 must show `parent_backlog_empty` and zero spawnable work **rather than pretending spare capacity is refill debt**."

因此 deficit 的计算不是：

```
deficit = target - running   ← 纯容量差，错误定义
```

而是：

```
deficit = min(target - running, spawnable_pending)
```

当 `spawnable_pending = 0`（即 pending=0 且 queue_empty=true），则：

```
deficit = min(20 - running, 0) = 0
```

**∀ running < 20：当 backlog 为空时，deficit=0 是唯一语义正确的值。**

空槽位 ≠ 亏欠。亏欠只有在存在真实工作时才成立。

---

### 反例：deficit=20-running 的错误后果

假设 running=5, pending=0, queue_empty=true，若错误地令 deficit=15：

系统将被迫合成 15 个 filler 包。这违反了：
1. §6 明确禁止合成 filler
2. §2 的 anti-polling 纪律（Sol 不得为凑数制造轮次）
3. §1 的分解纪律（每个包必须有真实的、有界的目标）

filler 包会消耗 token 预算、污染 KPI、触发 §8 的 25% Sol share BLOCK，同时不产生任何有用输出。

---

### 命题 2：pending>0 时应满足的必要不变量

设 `valid(p)` 表示工作包 p 满足 §1 的四字段要求（goal, authorized_paths, acceptance, constraints）且非 filler。

**不变量 I1（调度完整性）：**
```
pending > 0  →  ∃ p ∈ backlog: valid(p) ∧ ¬overlaps_authorized_paths(p, running_agents)
```
pending 计数中的每个包都必须是真实有效的、路径不冲突的工作包。

**不变量 I2（deficit 有界性）：**
```
deficit ≤ min(target - running, pending)
```
deficit 不得超过当前可调度的有效工作包数，也不得超过容量空缺。

**不变量 I3（非负性与单调性）：**
```
deficit ≥ 0
running + deficit ≤ target
```

**不变量 I4（backlog 一致性）：**
```
queue_empty = true  →  pending = 0
pending = 0  →  deficit = 0
```
这是一个传递性约束：空队列直接蕴含零 deficit，无论 running 多小。

**不变量 I5（sustained concurrency 触发条件）：**
```
deficit > 0  ↔  running < target ∧ pending > 0
```
当且仅当**同时满足**"有容量空缺"与"有真实工作"，才应触发补充。这是双向充要条件。

---

### Sustained Concurrency 目标 vs. Filler 的语义边界

| 概念 | 含义 | 何时为真 |
|---|---|---|
| Sustained concurrency goal | 在存在真实工作时尽量维持 target 并发 | pending > 0 |
| Refill obligation | 必须立即补充的槽位 | running < target ∧ pending > 0 |
| Spare capacity | 未使用的槽位，无义务填充 | running < target ∧ pending = 0 |
| Filler | 为凑数合成的无效包 | 永远禁止 |

sustained concurrency 目标是一个**条件性**目标，不是绝对性目标。其完整语义是：

> "当存在有界的、真实的独立工作包时，应持续保持接近 target 的并发数。"

当 backlog 耗尽时，目标自动降级为"保持当前运行的 agent 直至完成"，deficit 归零，8765 显示 `parent_backlog_empty`。这是正确的终态，不是异常。

---

**结论：** target=20, running<20, pending=0, queue_empty=true 时 `deficit=0` **语义正确**。空槽位在无实际工作时不构成亏欠，强行填充将违反 §1、§2、§6、§8 的多项纪律约束。
