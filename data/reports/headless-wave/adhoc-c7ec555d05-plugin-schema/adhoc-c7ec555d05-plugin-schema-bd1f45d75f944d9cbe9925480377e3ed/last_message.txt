ZCode 插件系统遵循契约定义的标准化结构，完全支持变量插值，并对清单文件有严格的模式规范。以下是根据安装实际观察到的核验结果：

### 1. 清单文件（Manifest）结构
ZCode 插件要求在根目录下的 `.zcode-plugin/plugin.json` (或兼容名 `.claude-plugin/`, `.codex-plugin/`) 中包含清单，其核心规范如下：

*   **必须字段**：`name` (严格符合 `^[a-z0-9][a-z0-9._-]{0,127}$`)。
*   **组件路径校验**：所有声明的 `commands`、`skills`、`hooks` 和 `mcpServers` 路径必须是相对于插件根目录的**相对路径**且**不得逃逸根目录**，否则会被 rejected。
*   **配置项注入**：`userConfig` 支持 `string`、`number`、`boolean`、`directory`、`file` 类型。**注意**：`sensitive: true` 的字段目前在客户端内无法输入或持久化。
*   **版本管理**：`version` 默认为 `0.0.0`。正式发布插件通常通过其 marketplace 和源追踪版本。

### 2. 变量插值支持
在 `plugin.json` 和 `.mcp.json` 声明的 MCP 服务器配置中，以下变量被系统运行时插值，用于解耦安装路径与底层实现：

*   **路径引用**：
    *   `${ZCODE_PLUGIN_ROOT}`：插件安装目录。
    *   `${ZCODE_PLUGIN_DATA}`：插件专属数据目录。
    *   `${ZCODE_PROJECT_DIR}`：当前活跃的项目/工作区根目录。
*   **用户配置数据**：
    *   `${user_config.<key>}`：直接映射 `plugin.json` 中 `userConfig` 定义的字段。系统解析器会在运行时用用户设置的值替换该占位符。

### 3. MCP 声明 Schema 与兼容性
MCP 服务器配置可同时存在于 `plugin.json` 的 `mcpServers` 字段和插件根目录的 `.mcp.json` 中。
*   观察到声明模式是一致的（均定义 `command`、`args`、`env` 等环境变量）。
*   在 `android-emulator` 插件的示例中，`plugin.json` 中使用 `${ZCODE_PLUGIN_ROOT}`，而 `.mcp.json` 中可能含有迁移遗留的 `${CLAUDE_PLUGIN_ROOT}` 语境，符合系统对早期兼容路径的识别逻辑。

### 4. 关键安装契约
*   **唯一性**：插件的身份在系统中由 `<name>@<marketplace>` 决定。
*   **持久化**：启用/禁用状态存储在 `~/.zcode/cli/config.json` 的 `plugins` 分支下，而非插件清单内。
*   **抑制机制**：对于内置的 Official 插件（无法物理删除），通过在 `plugins.suppressedBuiltins` 中记录 ID 来实现“卸载”效果。

**核验结论**：插件架构是声明式且受限的，组件路径隔离遵循最小权限原则，通过变量插值实现了配置驱动的环境注入，满足安全要求。
